## Карточки задач

### Д-1 · Отчёт живёт в базе: report_json + ответы брифа

- **Зачем:** РЕШ-146 (владелец, вариант А): `requests.report_json` +
  `briefs.owner_answers`, разовый ALTER без пересоздания. Сейчас отчёт —
  только markdown-файл; экрану Э3-5 и экспорту Э4-2 нечего читать. Таблица
  `briefs` мертва (РЕШ-156) — оживает или уходит: решение РЕШ-146 — оживает
  ответами брифа.
- **Файлы:** `models.py`, `pipeline/persistence.py`, `pipeline/run_flow.py`
  (передача отчёта в persist), тесты (`test_persistence.py` + новый).
- **Что делать:** колонка `report_json` (nullable TEXT/JSON) у requests;
  строка `briefs` пишется на прогоне (бриф + ответы, пока авто-режим — пустые
  ответы, поле есть); `persist_run` сохраняет сериализованный `Report`;
  функция чтения отчёта по request_id (слой persistence, для этапа 3).
  ALTER живой базы НЕ делать — его делает оркестратор при слиянии (урок
  Э2-Ж); в handoff — точные ALTER-команды.
- **Критерии:** прогон на подменах пишет и читает отчёт (сериализация
  обратима: Report → json → Report, тест); briefs > 0 строк после прогона
  на подменах; полный pytest 0 failed; ruff чист.
- **Мутации:** (а) report_json не пишется — тест чтения падает; (б) чтение
  возвращает сырой dict вместо Report — тест типа падает.
- **Норматив 3 ч, предел 4,5. Границы:** веб-маршруты не трогать (этап 3);
  экспорт markdown остаётся первичным артефактом CLI.

### Д-2 · Роспатент и arXiv: повтор с обобщением; разбор «21 без карточек»

- **Зачем:** живые числа Э2-Ж: Роспатент 1→20 на короткой формулировке;
  arXiv получает семисловные точные фразы и даёт 0. Образец решения уже в
  бою — укорачивание КиберЛенинки (З-2, cyberleninka.py: `_shorten_query`,
  один повтор, кэш по финальной форме, обе формы в лог).
- **Файлы:** `search/rospatent.py`, `search/arxiv.py`, их тесты,

- **Что делать:** тот же приём, что З-2, в обоих адаптерах (повтор ровно
  один, при пустой/единичной выдаче — порог повтора: found==0 у arXiv;
  у Роспатента повтор при < 3 кандидатов — переуточнение там душит не до

  один не дошёл до карточки (данные прогона 1 в БД нет — взять из отчёта

  только по следующему прогону, и поставить наблюдение в ворота).
- **Критерии:** respx-тесты повтора для обоих адаптеров (по образцу
  test_search_cyberleninka); темп/условия источников не смягчены; полный

### Д-6 · Семантический судья дублей: проба → промпт → подключение

- **Зачем:** РЕШ-152: лексика не разделяет дубли (пара 3–4 фармы 0.182 при
  недубле 1–5 0.571). Прагматичный семантический признак — судья-модель на
  МАЛОМ наборе: только отобранные перед группировкой (≤ 12 кандидатов,
  ≤ 66 пар, один вызов батчем).
- **Что делать:** (1) **проба** (РЕШ-133, скрипт вне поставки,
  `scripts/dedup_judge_probe.py` ≤ 500): взять дословные заголовки+сниппеты
  из `evidence/E2G-З6-similarity.md` (фарма 5, нефтегаз 6) с готовой ручной
  разметкой (3–4 дубль; 1–5 не дубль; группа 2-3-4-5 нефтегаза), прогнать
  промпт-судью на FakeProvider-подмене В ТЕСТАХ и ЖИВЬЁМ один раз
  (оркестратор, ~0,1–0,3 ₽) — точность против разметки в доказательство;
  (2) промпт `prompts/dedup_judge.md` (метки через render_prompt +
  EXPECTED_PLACEHOLDERS; ТЕКСТ ПРОМПТА — виза владельца при итоговом
  докладе, РЕШ-180 оговорил отдельную визу); (3) подключение: стадия перед
  `group_for_cards` спрашивает судью один раз, склейка использует спящую
  машинерию diversity (merge_duplicate_groups) с группами от судьи вместо
  лексического порога; отказ судьи — карточки как раньше (инвариант 5:
  деградация, не падение).
- **Критерии:** проба показывает точность на размеченных парах (число в
  доказательстве, живой вызов — оркестратор); стадия чистая (без БД);
  отказ судьи не роняет прогон (тест); +1 вызов модели на прогон — назван
  в оценке стоимости; полный pytest 0 failed.
- **Мутации:** (а) отказ судьи роняет прогон — тест падает; (б) судья
  склеивает всё в одну группу — тест «не больше N в группе»/здравый
  предел падает.
- **Норматив 4 ч, предел 6. Границы:** порог 0.65 лексики не трогать

## Ворота Э2-З

Шапка пишется до прогона. **Один живой прогон** — нефтепереработка, задача
Э2-А «гидроочистка дизельного топлива» (свежая отрасль в базе; КиберЛенинка
держит 720 статей). Критерии (доказательство обязательно): 1) прогон без
падения, стоимость названа; 2) ≥ 5 карточек основной секции; 3) покрытие
≥ 4 типов по БД; 4) **отчёт читается из БД** (report_json → Report), briefs
> 0; 5) сводка первичной моделью (deepseek) — по логу; 6) Роспатент > 3
кандидатов ИЛИ повтор-обобщение виден в логе; 7) судья дублей отработал
(или его отказ деградировал честно); 8) схема живой базы чиста по доктору;
9) страж-исключения длины пусты; 10) pytest 0 failed, ruff чист; 11) расход
волны ≤ 30 ₽ (включая пробу судьи и испорченные попытки).

Бюджет: кодовые задачи 0 ₽; проба судьи ~0,3 ₽; прогон 13–17 ₽; запас на
контрольный повтор. Платные вызовы — только оркестратор.
