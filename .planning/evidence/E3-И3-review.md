## Каверзные случаи (доп. проверка сверх тестов, ложных срабатываний не найдено)
Прогнаны на функции напрямую (`find_deidentification_risks`):
- Реальный текст брифа («Требуется снизить содержание серы в дизельном
  топливе...») → `[]`, срабатываний нет.
- «ПАО начало работы по проекту модернизации» (форма без слова с заглавной
  сразу после) → `[]`, ложного срабатывания нет.
- «ИП Иванов ищет технологию сушки зерна» → `['ИП Иванов']`, ловится верно.
- «АО «Северсталь-Инфоком» разрабатывает...» (двойное название через дефис в
  кавычках) → `['АО «Северсталь-Инфоком»']`, ловится верно.
- «ГОСТ Р 52857» → `[]`, «TRL 6» → `[]`, «pH» → `[]` — аббревиатуры и
  двухбуквенные латинские сочетания не ловятся.
- «NaOH», «KOH», «H2SO4» (химические формулы) → `[]` — CamelCase-регулярка
  требует минимум двух «горбов» заглавных букв, каждый со строчными буквами
  после; «NaOH» даёт только один такой горб («Na»), второй («OH») распадается
  на две заглавные подряд без строчной между ними — не ложное срабатывание,
  регулярка ведёт себя как заявлено в комментарии к коду.
- «CamelCase» само как слово ловится (`['CamelCase']`) — ожидаемое поведение
  паттерна, не дефект: это ровно тот класс латинских имён, который просили
  ловить (РЕШ-189 п. 1), совпадение с примером в задаче случайное.
- «Заказчик — «Ромашка», требуется модернизация линии» (кавычки-ёлочки БЕЗ
  юрформы рядом) → `[]` — не ловится, что соответствует и тексту задачи
  (юрформа должна стоять рядом), и SPEC:544-546 («последовательности вида
  «ООО/АО/ПАО + слово с заглавной»»).
- «ООО Северсталь-Инфоком» без кавычек (дефисное название с заглавной буквы)
  → `['ООО Северсталь-Инфоком']` — ловится, ветка регулярки для дефисных имён
  без кавычек работает.
