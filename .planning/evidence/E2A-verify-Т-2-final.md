## Правки аудита — все закрыты

**П-1.** Заголовок печатается ровно тогда, когда разделу есть что сказать.
Проба верификатора на `render_markdown`:

```
только недоступные источники     заголовок присутствует: True
только оговорки                  заголовок присутствует: True
оба сразу                        заголовок присутствует: True
оба пусты                        заголовок присутствует: False
```

Тест параметризован тремя случаями и проверяет не только наличие, но и
порядок — `lines.index(f"- {caveat}") > heading_at`.

**П-2.** Ответы в `owner_answers` (см. критерий 2). `_normalize_owner_answer`
делает `strip()` и сличает `casefold()` с `UNKNOWN_ANSWER`; тест параметризован
`"не знаю"` и `"  Не Знаю  "`. Умолчание диалога попадает под правило:
`typer.prompt(question.question, default=UNKNOWN_ANSWER)`, результат прогоняется
через нормализацию в той же строке.

**П-4.** `_intake_stage_record` снимает дельту через ту же
`orchestrator.cost_delta`, что и стадии пайплайна. Тест утверждает конкретные
значения, а не «не ноль»: `record.cost_rub == pytest.approx(0.02), "две
оплаченные попытки по 0,01 ₽"` и `record.provider == "gigachat"`.

**П-5.** `_persist_intake_stop` пишет `status="failed"` и
`cost_rub=round(router.cost.spent_rub, 4)`, после чего `raise` в обоих
обработчиках. Тест: `pytest.raises(CostLimitExceededError)`,
`requests[0].status == "failed"`, `requests[0].cost_rub ==
pytest.approx(99.0)`, `[(row.stage, row.cost_rub) for row in logs] ==
[("intake", pytest.approx(99.0))]`, плюс `captured == []`.

**П-6.** `neutralize_placeholders` схлопывает серии скобок. Механика верна:
`render_prompt` собирает промпт через `str.replace`, а не `str.format`, и ищет
остатки регуляркой по `{{...}}` — одинарная скобка ни под подстановку, ни под
проверку не подходит. Обезвреживание стоит в **двух** местах: в
`brief_from_raw_text` и на флаге `--industry`, то есть сырой ввод оператора
закрыт с обеих сторон.

**С-2.** Константы `STAGE_INTAKE = "intake"` и `STAGE_INTAKE_REFINE =
"intake_refine"`; тест утверждает `stages_logged == ["intake", "intake_refine"]`.

**Доводка.** Отказ `refine_brief` даёт собственную оговорку; тест утверждает
`caveats[-1] == [cli.REFINE_FALLBACK_CAVEAT]`, то есть именно свою, и
`INTAKE_FALLBACK_CAVEAT` в эту ветку не подмешивается.

Кусок готового отчёта:

```
## Ограничения этого поиска

Не ответили источники: rospatent. Выдача могла быть полнее — стоит повторить запрос позже.

- Уточнения по задаче не собраны: бриф составлен из текста задачи. Выдача может быть шире и менее точной, чем при уточнённой постановке.
- Постановка задачи осталась черновой: ответы на уточняющие вопросы получены и учтены при подборе, но в постановку не сведены.
```

**Нарушений инварианта №1 нет.** `REFINE_FALLBACK_CAVEAT` о качестве выдачи не
заявляет **ничего**: сообщает два проверяемых факта о самом прогоне и на этом
останавливается. Измерения «выдача хуже» не существует, и текст его не
выдумывает. `INTAKE_FALLBACK_CAVEAT` относится к другому случаю (брифа нет
вовсе, `constraints` пусты) и говорит о выдаче в модальности возможности
(«может быть»), а не факта; основание проверяемо внутри самого прогона: при
пустых `constraints` сверка требований пуста по правилу 18 промпта, а план
поиска строится без сужений.
