## Разбор логики
`_visible_summary` в `backend/app/verdicts.py` (после правки):

```python
rows = summary.comparison_rows
if not rows:
    return summary
kept = _kept_positions(main_cards, card_ids, effective, is_contest=False)
if len(kept) == len(main_cards):
    return summary  # отклонённых карточек нет — скрывать нечего
if len(rows) != len(main_cards):
    return summary.model_copy(update={"comparison_rows": []})
filtered_rows = [rows[position] for position in kept]
return summary.model_copy(update={"comparison_rows": filtered_rows})
```

- Сравнение `len(rows) != len(main_cards)` идёт с числом карточек **до**
  фильтра (`main_cards` — параметр `report.cards`, передан из `visible_report`
  до применения `_visible_section`), а не с `len(kept)` — критерий (в) задания
  выполнен, мутация поймана существовавшими тестами.
- Проверка «есть ли хоть одна отклонённая карточка» (`len(kept) ==
  len(main_cards)`) считается по основной секции (`is_contest=False`),
  конкурсная секция не участвует ни в счёте карточек, ни в счёте строк —
  соответствует РЕШ-206 («стадия `summarize` строит таблицу только по
  основной секции») и явно проверено тестом
  `test_visible_report_reject_в_contest_cards_не_трогает_строки_сравнения`
  (отклонена только конкурсная карточка → `comparison_rows` не тронуты).
- Порядок проверок логически корректен: сначала «пустые строки» (без
  изменений), затем «нет reject» (без изменений — критерий 2), затем
  «несовпадение числа» (скрыть — критерий 1), и только в конце обычный путь
  фильтрации (критерий 3).

## Переписанный тест
Исполнитель переписал `test_visible_report_не_трогает_строки_при_несовпадении_числа`,
который до правки закреплял именно тот баг, что нашёл аудит (несовпадение
числа строк + reject → строки печатаются нетронутыми). Переименован и
переформулирован в `test_visible_report_несовпадение_числа_строк_с_reject_прячет_таблицу`
(критерий 1, воспроизведение аудита: 3 карточки, 4 строки, карточка 1
отклонена → `comparison_rows == []`). Рядом добавлен новый тест
`test_visible_report_несовпадение_числа_строк_без_reject_не_трогает_таблицу`
(критерий 2), который закрывает старый сценарий «несовпадение без reject» —
он у старого теста не проверялся вовсе (старый тест всегда ставил reject).
Покрытие остальных случаев задачи Э4-П1 не потеряно — в файле по-прежнему
есть:
- `test_visible_report_пустые_строки_сравнения_без_reject_не_меняются`
  (критерий 3 Э4-П1: пустой `comparison_rows`, отчёт без reject);
- `test_visible_report_reject_в_contest_cards_не_трогает_строки_сравнения`
  (критерий 4 Э4-П1: reject в конкурсной секции);
- `test_visible_report_фильтрует_строку_сравнения_вместе_с_карточкой` и
  `test_visible_report_не_ловится_на_фильтр_по_позиции_после_фильтра_карточек`
  (критерий 1/5 Э4-П1: порядок оставшихся строк, адверсариальный тест на
  фильтрацию по позиции ДО, а не после фильтра карточек).

## Советы (не блокируют)
1. Комментарий `# отклонённых карточек нет — скрывать нечего` на строке
   `return summary` дублирует то, что уже подробно объяснено в docstring

   но это чистая вкусовщина.

   остальных клиентских фраз (короткий вариант в скобках ближе к нему).
