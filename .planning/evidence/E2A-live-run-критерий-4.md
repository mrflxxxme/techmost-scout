# Живой прогон: критерий приёмки 4 задачи Т-7 и проверка починки Т-13

**Итог: критерий 4 ЗАКРЫТ, починка скоринга (Т-13) ПОДТВЕРЖДЕНА.**

Прогон делал оркестратор: критерий требует платных вызовов, ролям они запрещены
инвариантом №7. Дерево `.claude/worktrees/E2A`, ветка `session/E2A` после
слияния Т-13.

## Команда

```
python -m app.cli run "Требуется снизить содержание серы в дизельном топливе
до 10 ppm на установке гидроочистки. Действующий катализатор теряет активность
за 8 месяцев вместо заявленных 24." --industry "нефтепереработка" --no-interactive
```

## Критерий 4 — обе половины

```
*Запрос №3 · 16.08.2026 19:32 · стоимость машинной обработки 7.55 ₽*
```

```
Стоимость запроса: 7.55 ₽; вызовов модели 33, из них с кэшем префикса 24
(кэш считается только у DeepSeek; у остальных провайдеров всегда 0)
```

Номер запроса больше нуля, строка счётчика кэша на месте с оговоркой из цикла
правок. Запись в БД: `(3, 'drafted', 7.552)` — `persist_run` вернул id, и он
доехал до отчёта.

**Побочно измерен эффект самой Т-7:** 24 попадания в кэш префикса из 33 вызовов,
то есть **73 %**. Перенос блоков подстановки в конец промптов дал измеримый
результат, а не только зелёный тест.

## Проверка починки Т-13 по критериям исполнителя

| Признак | До Т-13 | После |
|---|---|---|
| `скоринг батча не удался — беру нейтральные оценки` | на каждом батче | **0 раз** |
| Прогон доходит до отчёта | нет, снят по таймауту | **да**, 100 % |
| Оценки различаются между кандидатами | все нейтральные | **да**, 6 карточек с разными разборами |

Главный признак — полное отсутствие `скоринг батча не удался`. Ранжирование
живо: из 80 кандидатов после склейки дублей отобрано 6, каждая карточка несёт
свой разбор применимости и честно называет, чего в источнике нет («нет данных о
достижении 10 ppm, об активности после 24 месяцев эксплуатации»).

## Что осталось не идеальным — честно

Предупреждение `DeepSeek: content пуст, беру ответ из reasoning_content` на
стадии scorer **не исчезло**, и в логе появилось
`стадия scorer: ответ обрезан по лимиту токенов, переспрашиваю с лимитом 16000`.
По критерию 1 исполнителя это значит, что лимита 8000 всё ещё впритык: часть
батчей берётся со второй-третьей попытки. Отказа это больше не вызывает —
роутер эскалирует лимит и дожимает, — но стоит денег и времени.

Прогон занял около 21 минуты при назначенном нормативе 12. Это долг: либо
поднять лимит скоринга ещё, либо уменьшить `batch_size`, чтобы ответ на батч был
короче. **Уходит долгом к воротам Э2-А**, выпуск не блокирует.

## Стоимость

```
этот прогон                     7,55 ₽ (записан в БД)
прогон до починки, снят мной    ≈5-6 ₽ (в БД не записан: процесс снят до записи)
живой доктор и замер выдачи     ≈0,03 ₽
ИТОГО за сессию                 ≈13 ₽ из 40 ₽ (РЕШ-53)
```

Оценка снятого прогона восстановлена по числу вызовов модели: 33 вызова дали
7,55 ₽, снятый успел сделать порядка двух десятков. Точной цифры нет, потому что
`persist_run` до записи не дошёл — прогон был снят на стадии скоринга.

## Ошибки оркестратора в этом шаге

1. **Норматив 12 минут назначен по здоровому конвейеру** — прогон занял 21.
2. **Первый запуск упал на кавычках:** `Start-Process -ArgumentList` разбил текст
   задачи по пробелам, CLI получил лишние аргументы. Денег не стоило, стоило
   пяти минут ожидания.
3. **Первый платный прогон вообще не следовало назначать с нормативом «5 минут,
   0,3 ₽»** — здоровье конвейера надо было проверять до того, как называть цифру.
   Зафиксировано в РЕШ-65.
