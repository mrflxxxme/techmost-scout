HEAD https://new.fips.ru/    -> 200 text/html; charset=UTF-8
HEAD https://fips.ru/        -> 200
HEAD https://www.fips.ru/    -> 200
GET  https://www1.fips.ru/   -> 200, 79 105 байт,

## 1. Роспатент: открытые данные (часть А.1)

Числа по составу, объёмам и полям сняты разведкой 14 августа и лежат в
`E2A-patents.md` §1 — здесь не дублируются. Перепроверено и добавлено:

**Состав подтверждён повторно (ПРОВЕРЕНО, 17.08.2026).** `rospatent.gov.ru/opendata`
→ 200, **28 наборов** на срез **05.08.2026**. Из них по интеллектуальной
собственности — **девять**: `-iz` (изобретения), `-pm` (полезные модели),
`-po` (промобразцы), `-evm` (программы ЭВМ), `-bd` (базы данных),
`-tz` (товарные знаки), `-otz` (общеизвестные ТЗ), `-tims` (топологии ИМС),
`-nmpt` (географические указания и НМПТ). Остальные 19 — административные
(вакансии, проверки, госуслуги, НПА, план деятельности) и к поиску разработок
отношения не имеют.

**Периодичность.** В паспортах наборов ИС заявлено обновление **ежемесячно**;
фактический срез на день прогона — 05.08.2026, то есть лаг от начала месяца
около недели. Административные наборы обновляются реже (у `-planproverok`
заявлено «ежегодно»). Отдельного механизма дельт (инкрементальных поставок)
**нет**: каждый месяц публикуется полный снимок с новым именем файла.

**Формат.** На `rospatent.gov.ru/ru/sourses` заявлено, что открытые данные
доступны «в свободно выгружаемых форматах **CSV и XML**» (ИЗ ДОКУМЕНТА).
Фактически на страницах паспортов девяти наборов ИС разведка 14 августа нашла
**только CSV**; XML-выгрузки по наборам ИС не обнаружено. Расхождение
официального текста с фактическим содержимым **не разрешено** — считать
рабочим форматом CSV.

**Полнота полей — решающий факт, подтверждается.** По `structure-20180828.csv`
у `-iz` **46 полей**: номер, название, даты, заявка, авторы, патентообладатели,
приоритеты, `actual`, `publication_url`. **Реферата, формулы, описания и МПК
нет ни в одном из девяти наборов.** Это и есть причина, по которой открытые
данные сами по себе не закрывают патентный поиск: искать по смыслу не по чему,
только по названию (заполненность `invention_name` — 98,8 %).

**robots.txt (ПРОВЕРЕНО).** `rospatent.gov.ru/robots.txt` → 200, 335 байт:

```
User-agent: *
Allow: /
...
User-agent: *
Disallow: /ru/client
Disallow: /ru/patent-attorneys
```

Запрещены только личный кабинет и реестр патентных поверенных; `/opendata`
разрешён явно. Ahrefs и Semrush забанены целиком — на нас не распространяется.
**Автоматическая загрузка открытых данных robots.txt не нарушает.**

## 2. Поисковая платформа: ключ (часть А.2)

**ПРОВЕРЕНО, 17.08.2026:**

```
HEAD https://searchplatform.rospatent.gov.ru/                    -> 200 text/html (Server: openresty)
GET  .../patsearch/v0.2/search                                   -> 401
GET  .../patsearch/v0.2/similar_search                           -> 401
GET  .../patsearch/v0.2/docs/{id}                                -> 401
GET  .../patsearch/v0.2/user/register                            -> 401
GET  .../robots.txt                                              -> 200, но отдаётся HTML-оболочка SPA (robots.txt нет)
```

То есть **весь API закрыт токеном, включая любые попытки самостоятельной
регистрации через API**. Интерфейс — React-SPA, регистрация только через него.

**Что известно об условиях (ИЗ ДОКУМЕНТА).**

1. Сама платформа заявлена как **бесплатная и общедоступная**. Официальная
   новость Роспатента: платформа «запущена для всеобщего использования»,
   реализован «поиск сведений по мировому фонду изобретений и полезных
   моделей, включая российские массивы и массивы стран СНГ»; «для
   разработчиков реализован программный интерфейс API»
   (`rospatent.gov.ru/ru/news/novaya-cifrovaya-platforma-rospatenta`).
2. Объём фонда — «свыше **100 млн** охранных документов со всего мира»
   (вторичный источник `i-regions.ru`, ссылающийся на Роспатент; в первичной
   новости числа нет — считать ориентиром, не замером).
3. Способ получения ключа (первоисточник — документ «Открытые API ИС ПП»,
   найден разведкой 14 августа на `online.rospatent.gov.ru/docs/`): ключ
   выдаётся «только зарегистрированным пользователям, в разделе
   „Генерирование ключей" пользовательского интерфейса системы».

**НЕ УСТАНОВЛЕНО, и это честный результат прогона:**

- **Кому выдают** — есть ли ограничение по типу пользователя (физлицо /
  юрлицо / только российские организации). Публичного критерия не найдено.
- **Сроки рассмотрения** — есть ли вообще модерация заявки или ключ выдаётся
  самообслуживанием сразу после регистрации. Ни в одном источнике не сказано.
- **Лимиты запросов** — ни числа запросов в сутки, ни RPS, ни квоты. В
  документации API описан только `limit` до 10 000 записей **в одном ответе**,
  что к частоте обращений отношения не имеет.
- **Публичной оферты или регламента доступа не существует.** Проверены:
  `rospatent.gov.ru/ru/sourses`, `online.rospatent.gov.ru/open-data/open-api`
  (страница есть, но это SPA — содержимое подгружается скриптом и внешнему
  чтению не отдаётся; попытки достучаться до её данных через
  `/api/v1/documents/`, `/api/v1/docs/`, `/api/v1/opendata/documents/`,
  `/api/v1/opendata/open_api/`, `/api/v1/settings/` дали **404**), новости
  Роспатента, отраслевые публикации. Условий нет ни в одном.

**Практический вывод.** Единственный способ узнать условия — **зарегистрироваться
на платформе и посмотреть раздел «Генерирование ключей»**. Регистрация
бесплатная и по РЕШ-55 п. 3 прямо разрешена («новым ключом» не считается).
Разведка этого не делает: правила прогона запрещают заводить аккаунты и
отправлять формы. Это действие владельца — оно и вынесено в эскалацию как
вариант А.

## 3. Трудоёмкость локального индекса (часть А.3)

Считано по фактическим объёмам из `E2A-patents.md` §1.

**Объём хранения.** Девять наборов ИС целиком:

| Подмножество | Байт | ≈ |
|---|---|---|
| Всё девять наборов ИС | 1 846 845 588 | **1,72 ГиБ** |
| Технически релевантное подмножество (`-iz`, `-pm`, `-evm`, `-bd`, `-tims`) | 1 084 580 860 | **1,01 ГиБ** |
| Из него один `-iz` (изобретения) | 695 120 416 | 663 МиБ |

Товарные знаки (`-tz`, 655 МиБ) и промобразцы (`-po`, 59 МиБ) для поиска
технических разработок бесполезны — исключены из подмножества.

Записей в релевантном подмножестве: ~776 000 изобретений + ~229 000 полезных
моделей + ~301 000 программ ЭВМ + ~42 000 БД ≈ **1,35 млн строк**.

**SQLite с индексами** по номеру, году, патентообладателю плюс FTS5 по
названию: названия коротки (реферата нет), поэтому полнотекстовый индекс
дешёвый. Оценка: **1,5–2,5 ГБ на диске** под релевантное подмножество,
**2,5–4 ГБ** если тянуть все девять наборов.

**Время первичной загрузки.** Скачивание 1 ГиБ (`Accept-Ranges: bytes`,
докачка есть) — единицы минут на нормальном канале. Разбор 1,35 млн строк
CSV с переносами внутри кавычек настоящим парсером и вставка батчами —
десятки минут. **Итого от 20 до 60 минут разовой машинной работы**, без
человека. Инженерная работа (разбор паспорта, кодировки, схема, идемпотентная
перезаливка) — **отдельная задача подэтапа реализации, порядка одного
рабочего дня**, точная оценка — за планировщиком, не за разведкой.

**Схема обновления.** Дельт нет, поэтому единственный корректный путь —
**полная ежемесячная перезаливка**: раз в месяц разобрать страницу паспорта
(имя файла меняется: `data-20260805-structure-20180828.csv`), скачать ~1 ГиБ,
залить в новую таблицу, атомарно подменить. Трафик ~**1 ГиБ в месяц**.
Ловушки известны и записаны 14 августа: BOM, запятая-разделитель, переносы в
кавычках, а файл структуры — наоборот windows-1251 с точкой с запятой.

**Чего локальный индекс не даст никогда.** Ни реферата, ни МПК, ни формулы, ни
цитирований. Отбор кандидата по смыслу невозможен — только по вхождению слов в
название. Для проверки патентной чистоты (FR-7) этого мало: разработка,
названная «Способ обработки углеводородного сырья», не найдётся по запросу про
конкретную технологию гидроочистки. **Локальный индекс — это точный реестр
«что зарегистрировано и кем», а не поисковик по содержанию.**

## 4. ФИПС: технические пути (часть Б, РЕШ-68 п. 3)

### 4.1 Доступ есть — и это главное изменение

См. §0: все четыре хоста ФИПС отвечают 200 из этой сети 17 августа.
Дополнительно ПРОВЕРЕНО, что живы и внутренние подсистемы:

```
GET https://www1.fips.ru/iiss/           -> 200, 52 158 Б, <title>Информационно-поисковая система</title>
GET https://www1.fips.ru/iiss/db.xhtml   -> 200, 52 158 Б  (выбор баз данных)
GET https://www1.fips.ru/iiss/search.xhtml -> 200, 51 438 Б (форма поиска)
GET https://www1.fips.ru/registers-web/  -> 200, 24 712 Б, <title>Открытые реестры</title>
GET https://www1.fips.ru/publication-web/ -> 200, 33 814 Б, <title>Официальные публикации</title>
GET https://www1.fips.ru/opendata/       -> 404
GET https://www.fips.ru/opendata/        -> 404
```

Технология ИПС — **JSF/PrimeFaces 6.x** (`javax.faces.resource`, `jsessionid`
в URL). Это важно для оценки: сервер-сайд-состояние, `ViewState`, сессионные
куки — интерфейс, спроектированный под человека, а не под программу.

**Собственного реестра открытых данных у ФИПС нет** — `/opendata/` даёт 404 на
обоих хостах. Открытые данные публикует Роспатент (§1), не ФИПС.

### 4.2 Регистрация не нужна для бесплатных баз

ИЗ ДОКУМЕНТА (`www1.fips.ru/elektronnye-servisy/informatsionno-poiskovaya-sistema/`),
дословно:

> «Для поиска в БД просто нажмите на кнопку «Перейти к поиску», вход в
> поисковую систему (ИПС) осуществляется без ввода логина/пароля.»

**Бесплатно и без логина** доступны, в том числе:

- **рефераты российских изобретений на русском языке**,
- **рефераты российских изобретений на английском языке**,
- формулы российских полезных моделей,
- программы для ЭВМ, базы данных, топологии ИМС (с 2013 г.),
- полные тексты российских изобретений — **последние 3 бюллетеня**,
- МПК (редакция 2026.01), МКТУ (13-я ред. 2026), МКПО.

Список баз снят с `/iiss/db.xhtml` ПРОВЕРЕНО — 13 позиций, кнопка «Войти» на
странице есть, но она нужна не для входа в бесплатные базы.

**Платно** (ИЗ ДОКУМЕНТА, та же страница): полные тексты изобретений за весь
архив, товарные знаки, промышленные образцы, документы 1924–1993 гг.
Единица оплаты — «**Единицей оплаты считается один запрос**», ставки разные
для ТЗ и остальных баз. Оплата картой или банковским платежом после
регистрации. Поддержка: `helpdesk@rupto.ru`.

Отдельно подтверждается прежний факт из FAQ Роспатента: БД рефератов
российских патентных документов на русском и английском **с 1994 г. по н. в.**
даётся бесплатно, с поиском по ключевым словам и МПК.

**То есть именно то, чего нет в открытых данных — рефераты и МПК — у ФИПС есть
бесплатно и без регистрации.** Это и есть ответ на «содержит очень много
полезного».

### 4.3 Стоп-сигнал: robots.txt ФИПС запрещает всё нужное

ПРОВЕРЕНО: `https://www1.fips.ru/robots.txt` → 200, 15 130 байт, 695 строк
правил. Для `User-agent: *`:

```
Disallow: /iiss/
Disallow: /registers-web/
Disallow: /registers-doc-view/
Disallow: /publication-web/
Disallow: /publication-web/publications/
Disallow: /publication-rss/
Disallow: /publication-ws/
Disallow: /fips_servl/
Disallow: /ofpstorage/
Disallow: /Archive/   /Archive4/   /publications/   /Classifications/  ...
```

**Все три подсистемы, которые нам интересны — ИПС, открытые реестры,
официальные публикации — закрыты для автоматического обхода явным
`Disallow`.** Капчи нет, DDoS-Guard пропускает, технически запрос проходит —
но правило владельца сайта сказано прямо.

Это ставит границу ровно там же, где владелец её уже поставил по Google
(РЕШ-55): **программный обход ИПС ФИПС мы не строим.** Не потому что не
получится, а потому что это нарушение заявленного правила, и под системой,
которую показывают промышленному заказчику, такой фундамент не держится.
Ручное использование ИПС человеком robots.txt не регулирует — оператор
проекта пользоваться ФИПС может и должен.

### 4.4 Что тогда остаётся законного

1. **ИПС ФИПС как ручной инструмент оператора.** Бесплатно, без логина,
   рефераты + МПК с 1994 г. Оператор проверяет патентную чистоту финальных
   кандидатов руками. Это работает уже сегодня, кода не требует и покрывает
   FR-7 в ручном режиме.
2. **Открытые данные Роспатента** (§1) — легально автоматизируемый слой:
   реестр «что зарегистрировано и кем», ежемесячно, robots.txt разрешает.
3. **Поисковая платформа Роспатента по ключу** (§2) — единственный законный
   *программный* путь к российским рефератам, формулам и МПК, включая
   `similar_search` по произвольному тексту. Ради этого и стоит регистрация.
4. **`online.rospatent.gov.ru`** — отдельный хост, DDoS-Guard там не мешал
   и 14 августа; его robots.txt (23 953 байта) — это стандартный
   «bad-bot blocklist» (AhrefsBot, SemrushBot, сканеры уязвимостей и т. п.),
   а не запрет содержательных разделов. Открытые реестры на нём отвечали 200.
   Схема XHR-запросов так и **не установлена** (`search_by_registries` отдаёт
   `{}` на все подобранные полезные нагрузки) — путь остаётся неразобранным.

**Чего разведка НЕ предлагает** и предлагать не будет: смены выхода в сеть
ради ФИПС, обхода DDoS-Guard, игнорирования robots.txt, эмуляции браузера
против JSF-сессий. Владелец спрашивал «как достучаться» — ответ оказался
проще: **из вашей сети ФИПС и так открывается, а программного канала у него
нет и не предполагается; программный канал называется «поисковая платформа»
и открывается регистрацией.**

| **PatentsView** `api.patentsview.org` | — | отдаёт HTML-заглушку, не JSON | **нет, US-only**; API выключен, миграция в USPTO ODP 20.03.2026 |
| **USPTO ODP** | да, через ID.me | не пробовалось | US-only |
| **WIPO PATENTSCOPE** | нет для веб-интерфейса | `search.jsf` → **200**; `rss.jsf` → **404** | RU есть, но **официального API нет** |
| **BigQuery `patents-public-data`** | аккаунт Google | не пробовалось в этом прогоне | RU через DOCDB, т. е. слабое |
| **Роспатент opendata** | нет | 200, robots разрешает | **полное по RU, но без рефератов и МПК** |
| **ИПС ФИПС** | нет (бесплатные БД) | 200, но `Disallow: /iiss/` | **полное по RU, с рефератами и МПК** |
| **Поисковая платформа** | да (регистрация) | 401 на всех эндпоинтах | **полное по RU + мировой фонд** |

**Новое за прогон — EPO Linked Open Data.** `https://data.epo.org/linked-data/`
отвечает 200, SPARQL-эндпоинт `/linked-data/query` принимает запрос без
какой-либо авторизации и возвращает `application/sparql-results+json`.
Это официальный публичный SPARQL EPO. **Не установлено:** глубина покрытия и
есть ли там рефераты — проверялось только то, что эндпоинт живой и отвечает на
произвольный SPARQL. Как источник по RU почти наверняка бесполезен по той же
причине, что и DOCDB (RU в EPO-массивах практически нет), но как канал к
европейским семьям и правовому статусу — кандидат, не требующий ни ключа, ни
скачивания 219 ГБ.

**Готовые инструменты (MCP-серверы, библиотеки).** Разведка 14 августа
заключила «брать нечего» (`E2A-patents.md` §3). Проверка 17 августа этот вывод
**подтверждает и уточняет**: существующие патентные MCP-серверы
(`patent-mcp-server` на PyPI, `riemannzeta/patent_mcp_server`,
`Rumblingb/patent-search-mcp`, «Patent Connector») построены на USPTO ODP /
Patent Public Search / Google Patents / EPO OPS. **Ни один не работает с
российскими источниками.** Часть требует ключей (ODP, OPS), часть строится на
скрейпе Google Patents — то, что владелец запретил (РЕШ-55). Один заявляет
платный тариф $19/мес. Для нашей задачи — русские патенты с рефератами — среди
них нет ничего.

Отдельная деталь, полезная на будущее: **USPTO Patent Public Search API ключа
не требует**, но имеет лимиты частоты и прямо не предназначен для массовой
выгрузки. Для точечной проверки американского аналога — годится; для RU —
бесполезен.

## 6. Что не выяснено

Честный список — по требованию задачи:

1. **Условия ключа поисковой платформы**: кому, платно ли, сроки, лимиты.
   Публичной оферты и регламента не существует; узнаётся только изнутри
   личного кабинета после регистрации.
2. **Открылся ли ФИПС насовсем** или это временное состояние отказного списка
   DDoS-Guard. Один замер в один день — не гарантия.
3. **Расхождение «CSV и XML»** в официальном тексте Роспатента с фактическим
   наличием только CSV.
4. **Схема XHR открытых реестров** `online.rospatent.gov.ru` —
   `search_by_registries` отвечает 200, но пустым `{}`.
5. **Покрытие и состав EPO Linked Open Data** — проверена только живость
   эндпоинта.
6. **Точное число записей** в наборах открытых данных — экстраполяция по
   срезам, полной загрузки не делалось.

## 7. Эскалация владельцу (§9)

Развилка РЕШ-14 закрывается выбором между двумя вариантами. Оба **не
взаимоисключающи** — но начинать нужно с одного.

### Вариант А — ключ поисковой платформы Роспатента

**Что делаете вы.** Регистрируетесь на `searchplatform.rospatent.gov.ru`
(бесплатно, разрешено РЕШ-55 п. 3), заходите в раздел «Генерирование ключей»,
создаёте ключ и присылаете его. Заодно — единственный способ узнать реальные
лимиты и увидеть, есть ли модерация: **это выяснится за те же пять минут**.

**Цена.** Ваше время: оценочно 10–20 минут, если регистрация самообслуживанием.
Если окажется модерация — плюс неизвестное ожидание. Денег, по всем найденным
источникам, не требует: платформа заявлена как общедоступная и бесплатная.
Риск: условия могут оказаться иными, чем ожидается, — они нигде не опубликованы.

**Что получаете.** Единственный законный **программный** доступ к российским
патентам **с рефератами, формулами, описаниями, МПК и цитированиями**, плюс
мировой фонд «свыше 100 млн документов». Ключевое для нас —
`similar_search`: поиск похожих по фрагменту произвольного текста от пары
предложений до нескольких абзацев. Это ровно та операция, которую делает
скаутинг: взяли описание задачи заказчика — получили релевантные патенты. Ни
один другой доступный путь этого не даёт.

**Следствия.** Патентная линия закрывается по-настоящему: FR-7 получает
машинную проверку, а не ручную. Появляется зависимость от одного ключа и от
неизвестных пока лимитов — но ключ бесплатный и отзыв его не ломает остальную
систему.

### Вариант Б — локальный индекс открытых данных

**Что делаем мы.** Загрузчик паспортов `rospatent.gov.ru/opendata`, разбор
CSV девяти (или пяти релевантных) наборов, SQLite с индексами и FTS5 по
названию, ежемесячная полная перезаливка.

**Цена.** ~1 ГиБ трафика и **1,5–2,5 ГБ диска**; первичная загрузка
20–60 минут машинного времени; инженерная работа порядка **одного рабочего
дня** в отдельном подэтапе. Вашего времени — ноль. Ключей — ноль.
Ежемесячно ~1 ГиБ трафика и полная перезаливка.

**Что получаете.** Полный и точный **реестр** российских изобретений,
полезных моделей, программ ЭВМ и БД: номер, название, дата, заявка, авторы,
патентообладатели, признак действия охраны, ссылка на публикацию. Работает
офлайн, ни от кого не зависит, лимитов нет.

**Следствия — и это главное.** **Реферата, МПК и формулы там нет.** Искать
можно только по вхождению слов в название, а названия патентов пишутся нарочно
обобщённо. Для проверки патентной чистоты по смыслу задачи этого
недостаточно — вариант Б даёт справочник, а не поисковик. Плюс постоянная
статья обслуживания: имя файла меняется каждый месяц, ломкий парсинг.

### Рекомендация оркестратора

**Начинать с варианта А, вариант Б — не сейчас.**

Причина простая: варианты решают разные задачи, и наша задача — первая.
Скаутингу нужен поиск по смыслу («вот проблема заказчика — что уже
запатентовано»), а его даёт только `similar_search` платформы. Вариант Б
отвечает на другой вопрос — «существует ли патент с таким номером и кто
правообладатель», — который в MVP второстепенен. При этом вариант А стоит вам
двадцати минут и ноля рублей, а вариант Б стоит нам рабочего дня и даёт
заведомо неполный результат. Тратить день на заведомо слабый инструмент,
не проверив пятиминутный сильный, — прямая переделка.

**Порядок действий, который предлагается закрепить решением:**

1. Вы регистрируетесь на платформе и пробуете сгенерировать ключ. Попутно
   выясняются условия и лимиты — то, что разведка установить не смогла.
2. **Если ключ выдали** — патентная линия строится на платформе; открытые
   данные откладываются в бэклог как «точный реестр для обогащения карточки»,
   а не как поисковый слой.
3. **Если ключ не выдали или лимиты непригодны** — включается вариант Б плюс
   ИПС ФИПС в ручном режиме для оператора; тогда же честно фиксируется, что
   машинной проверки патентной чистоты в MVP не будет.
4. ФИПС отдельным вариантом **не выносится**: доступ у вас и так есть,
   программного канала у него нет, а `robots.txt` прямо запрещает обход ИПС.
   ФИПС остаётся ручным инструментом оператора — бесплатным, с рефератами и
   МПК с 1994 года.

**Отдельный вопрос, требующий вашего ответа.** Подтвердите, пожалуйста, что
граница по `robots.txt` ФИПС понята так же, как граница по Google (РЕШ-55):
ИПС мы программно не обходим, даже когда технически проходит. Если ваша
позиция иная — это меняет весь §4.
