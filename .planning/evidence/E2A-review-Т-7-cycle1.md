## Блокирующая находка

### Н-1 · три новых теста кэша падают в чистом окружении

`tests/test_llm_router.py`:
`test_cache_hit_increments_cached_calls`,
`test_call_without_cache_hit_does_not_increment_cached_calls`,
`test_cached_calls_counts_only_cached_of_several`.

Доказательство `E2A-T7-pytest.txt` (строки 74–76) заявляет для них PASSED.
Воспроизведено дважды.

**Корень.** Фикстура `settings()` в `tests/conftest.py` вызывает
`Settings(deepseek_api_key=..., gigachat_auth_key=..., yandex_api_key=...,
yandex_catalog_id=...)` — по именам Python-полей. У этих полей в
`backend/app/config.py` задан `validation_alias` (`DEEPSEEK_API_KEY` и т. д.), а
`model_config` не содержит `populate_by_name=True`. При `extra="ignore"`
pydantic-settings молча отбрасывает kwarg по «неправильному» имени и оставляет
поле пустым `SecretStr("")`:

```
Settings(deepseek_api_key="sk-test").deepseek_api_key.get_secret_value()  ->  ''
Settings(DEEPSEEK_API_KEY="sk-test").deepseek_api_key.get_secret_value()  ->  'sk-test'
```

Из-за этого `DeepSeekProvider(settings)` видит пустой ключ, `complete()` бросает
`LLMError("не задан DEEPSEEK_API_KEY")` до похода в respx-заглушку, роутер
перебирает цепочку и падает с «все провайдеры отказали».

**Дефект не новый.** Он в `tests/conftest.py` и `backend/app/config.py`, которых
нет в списке файлов Т-7, и раньше был безобиден: все прежние тесты используют
`FakeProvider`, а не настоящие классы провайдеров. Тесты Т-7 — первое место в
наборе, где напрямую конструируется `DeepSeekProvider(settings)` и вызывается
`.complete()`. Задача первой наткнулась на давнюю дыру фикстуры.

Блокировку это не снимает: критерий приёмки 2 карточки Т-7
(«`pytest tests/test_llm_router.py -v` — зелёный») на чистой машине не
выполняется.

   `tests/test_cli_run.py` этого контракта не содержит. По литмус-тесту §9
   решение минимально и обоснованно. Отмечен пробел планирования: список файлов
   Т-7 не предусмотрел теста для пункта 4.
2. **Признанная дыра покрытия.** Строка счётчика кэша в `backend/app/cli.py` не
   покрыта юнит-тестом. Соответствует структуре критериев: критерий 4 (живой
   прогон) делегирован оркестратору, а логика `CostTracker.cached_calls`
   юнит-тестами закрыта.
3. **Формулировка может ввести в заблуждение.** `Usage.cached` выставляется
   только в `backend/app/llm/deepseek.py:130`; в `gigachat.py` и `yandex.py`
   поле всегда `False` (других присвоений `cached=` в `backend/app/llm` нет).
   Строка «вызовов модели N, из них с кэшем префикса M» не поясняет, что M
   считает только DeepSeek — на прогоне через GigaChat M всегда 0, что читатель
   волен принять за «кэш не работает». Не клиентский текст (`console.print`, не
   экспортируемый отчёт), поэтому не блокирует.
4. **Хрупкость `prompts/CHANGELOG.md`.** Версии `1.1`, `1.2`, `2.0` встречаются
   по два раза с разным содержимым. Коллизий сейчас нет: для каждого файла
   упоминающие его записи идут от новых к старым. Работает, но полагается на
   дисциплину «новая запись сверху» без машинной проверки порядка.
