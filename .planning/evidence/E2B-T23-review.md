## Решение шире буквы задачи, принятое исполнителем

Адаптер штамповал кандидату `source_type=SourceType.WEB` **жёстко**. При таком
коде ни один кандидат никогда не получил бы тип `CONTEST` — и потолок зрелости
Т-22 (`cap_contest_maturity` смотрит на `candidate.source_type`), и секция Т-24
остались бы мёртвыми так же, как был мёртв сам тип.

Теперь кандидат размечается типом формулировки:
```python
self._to_candidates(root, limit=limit, source_type=query.source_type)
```
Согласовано с уже существующим поведением стадии извлечения
(`stages.extract_candidates(query.source_type, ...)`), которая навязывает тип
кодом так же — разбор адаптера и разбор модели больше не дают разный тип.

**Это третья находка класса «сущность заведена, но не доходит» подряд:** тип в
схеме без приёма адаптером (Т-22 → Т-23), приём адаптером без разметки кандидата
(эта), разметка кандидата без деления карточек (Т-24 → Т-33).

## Слепой тест, найденный исполнителем

`test_предел_платных_запросов_на_прогон` задаёт `max_queries=6` **явно**, поэтому
изменение значения по умолчанию проходит мимо него. Свой тест исполнитель
написал рядом, чужой не трогал (§3). Подтверждение слепоты мутацией заказано
верификатору — пойдёт в ворота установленным фактом.

## Что сделано по существу

- `source_types = (SourceType.WEB, SourceType.CONTEST)`;
- конкурсная ветка сужения стоит **до** грантовой, потому что слово «конкурс»
  есть и среди грантовых маркеров; конкурсы сужаются по `source_type`, гранты —
  по маркерам текста;
- `CONTEST_SITES`: `hacks-ai.ru`, `leaders-of-digital.ru`, `all-cups.ru`,
  `codenrock.com`, `upgreat.one`, `sk.ru`, `devpost.com`;
- предел платных запросов не поднят — 6 как было;
- промпты правлены **в паре**: `planner.md` 2.3 и `replanner.md` 1.1, обе записи
  в `CHANGELOG`. Без второго второй проход конкурсы потерял бы.
