## 1. Корректность — симметрия сверки (главный вопрос)

**Симметрия держится по построению, а не как набор частных случаев.** Проба 1 —
29 пар «сырая запись ↔ ссылка кандидата», где правая сторона строится ровно как
в проде (`str(HttpUrl(...))`):

```
дословная копия, кириллический путь           СОВПАЛИ   'a.ru/%d1%81%d1%82%d0%b0%d1%82%d1%8c%d1%8f'
дословная копия, домен .рф                    СОВПАЛИ   'xn--80aa3ak5a.xn--p1ai/%d0%bd%d0%be%d0%b2...'
сырое закодировано ВЕРХНИМ, кандидат литерал   СОВПАЛИ   'a.ru/%d1%81%d1%82'
сырое литерал, кандидат закодирован ВЕРХНИМ    СОВПАЛИ   'a.ru/%d1%81%d1%82'
порт 443 слева / порт 443 справа / порт 80     СОВПАЛИ
точечные сегменты /x/../page                   СОВПАЛИ   'a.ru/page'
регистр домена / IPv6-литерал                  СОВПАЛИ
пробел в адресе / пробел -> %20 у кандидата    СОВПАЛИ   'a.ru/my%20page'
без схемы слева (https и http справа)          СОВПАЛИ
схема-относительный //a.ru                     СОВПАЛИ
хвостовой слэш / якорь / параметры             СОВПАЛИ
ВЫДУМКА: другой домен / усечённый путь /
         чужой путь на том домене              РАЗОШЛИСЬ (защита цела)
```

Регистр percent-кодирования снимается не поправкой, а тем, что `normalize_url`
опускает регистр всей строки; кириллица и `.рф` — тем, что обе стороны
прогоняются через тот же `HttpUrl`, что построил `candidate.url`.

**Проба 2 — ключевое свойство «модель скопировала запись ДОСЛОВНО → кандидат
обязан уцелеть», 25 форм записи адреса:**

```
асимметрий при дословном копировании: 0 из 25
идемпотентность _canonical_url: нарушений 0
```

Формы, отвергнутые как «кандидат с таким адресом невозможен»
(`наука.рф/новости` без схемы, `ftp://`, `https://`, `http://a b.ru/x`, адрес
> 2083 знаков), падают не на сверке, а раньше — на `Candidate.url`, то есть до
дельты и вне её.

Три расхождения из пробы 1 (`a.ru//page` vs `a.ru/page`, `u@a.ru` vs `a.ru`,
`%41` vs `A`) — это случаи, где **модель изменила адрес**, а не скопировала: при
дословной копии все три совпадают (проба 2). Это работа защиты, а не асимметрия.

**Вывод по п. 1 задания: Н-2 прошлого аудита снят по существу, новой асимметрии
не найдено.**

## 2. Корректность — откат `except ValidationError` и дописывание схемы

Проба 3, вопрос «может ли негодная сырая запись впустить выдуманного
кандидата»:

```
сырое 'ftp://a.ru/page'       -> ключ 'a.ru/page'            впускает: ['https://a.ru/page']
сырое 'https://'              -> ключ ''                     впускает: []
сырое 'http://a b.ru/x'       -> ключ 'a b.ru/x'             впускает: []
сырое 'https://a.ru/xxx…2100' -> ключ 'a.ru/xxx…'            впускает: []
сырое 'javascript:alert(1)'   -> ключ 'alert(1)'             впускает: []
сырое 'тыры-пыры'             -> ключ 'xn----3tbbcg8cbcb'    впускает: []
сырое 'a.ru'                  -> ключ 'a.ru'                 впускает: ['https://a.ru/']  (верно)
```

Откат дыры не открывает: ключ из невалидного адреса не совпадает ни с одним
канонизированным адресом кандидата, кроме кросс-схемного `ftp→https` (та же
страница, схему `normalize_url` отбрасывает и до дельты). Пустой ключ `''`
недостижим справа — у кандидата всегда есть хост. Годного кандидата откат не
роняет: путь достижим только для записей, которые `Candidate.url` и так не
принимает.

Дописывание `https://` разные адреса в один не склеивает: `a.ru` впускает только
`https://a.ru/`; проба на 29 + 25 формах ложного слипания не дала.

## 10. Находки

**Правка П-1 (долг к воротам).** `stages.py`, ветка
`except ValidationError: return normalize_url(raw)` в `_canonical_url` — новое
поведение без теста: мутация М-3 переживает целевой прогон (74 passed при
собранном мутанте, diff в таблице). Формально §5/инвариант №8. **Почему не
блокирует:** реальное следствие ветки прогнано (проба 3) — выдуманного
кандидата она не впускает, годного не роняет, единственный наблюдаемый эффект
кросс-схемный `ftp→https`, безобидный. Требование РЕШ-62 — блокировать только по
воспроизводимой пробе вреда; такой пробы нет.

**Правка П-2 (долг к воротам).** Частично отброшенные кандидаты не попадают в
`problems`, пока список не пуст — снаружи видна только строка лога. Класс «отказ
скрыт от отчёта» (инв. №5). Введён не этой дельтой; дельта его сузила. Ложного
срабатывания на 25 формах дословной копии не найдено, поэтому это долг, а не
блокирующее.

**Советы (не блокируют):**

1. С-1. `.strip()` в `_canonical_url` декоративен — pydantic и `normalize_url`
   обрезают пробелы сами (М-5 эквивалентна). Строка обещает больше, чем делает.
2. С-2. Сырая запись с чужой схемой (`ftp://`) впускает `https://`-кандидата:
   `normalize_url` схему отбрасывает. Поведение до дельты, вреда не показано.
3. С-3. Сырая запись длиннее 2083 знаков теряет кандидата на схеме
   `Candidate.url` до всякой сверки, с логом «запись отброшена». Состояние до
   Т-6.
4. С-4. Ключ из мусорной записи (`'тыры-пыры'` → `xn----3tbbcg8cbcb`) молча
   попадает в множество допустимых адресов — безвреден, но мусор в множестве.
5. С-5. Порядок строк `SearchOutcome.problems` от прогона к прогону разный
   (совет 2 цикла 2) — журналы двух прогонов текстом не сравнить.

**Четыре совета прошлого аудита — стал ли какой-то блокирующим: нет, ни один.**
Совет 1 (невидимость частичного отбрасывания) поднят до правки П-2. Совет 2
(порядок `problems`) — повторён как С-5. Совет 3 (`StageRecord.error` не доходит
