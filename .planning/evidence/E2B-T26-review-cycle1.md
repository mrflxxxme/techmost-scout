## Главный вопрос ревью: объём диффа — оправдан

Оркестратор поставил вопрос прямо: 194 изменённых строки в `stages.py` для
задачи «поднять одно число и добавить одну строку лога» — не рефакторинг ли
«пока рядом», запрещённый §5 и инвариантом №9.

**Ответ фактический: цифра 194 обманчива.** `git diff -w` (без учёта отступов)
даёт **92 изменённые строки вместо 194 и 17 удалённых вместо 68**. Разница —
тело цикла `for start in range(...)`, целиком сдвинутое на 4 пробела вправо,
потому что въехало внутрь `try:`. По существу эти ~51 строка не изменились.

Все 17 реальных удалений:

| Что | Строк | Оправдано |
|---|---|---|
| Комментарий Т-13, заменённый переформатированной версией с абзацем Т-26 | 15 | да — комментарий к той самой строке, которую меняет задача |
| `max_tokens=8000` | 1 | да — это и есть работа задачи |
| f-строка, разбитая надвое | 1 | вынужденно: исходная длина ровно 120 знаков при `line-length = 120`, +4 отступа = 124, иначе `ruff format` не проходит |

**Ни одной строки логики не удалено.** Ветки `except CostLimitExceededError`
с `raise`, `except Exception` с нейтральными оценками, пропуск кандидата по
`by_index.get(position) is None` — все на месте, проверены построчно.

**`_TokenRetryCounter` — не «пока рядом», а единственный способ выполнить пункт
2 в отведённых задаче файлах.** Повтор по нехватке лимита происходит **внутри**
`LLMRouter.complete_json` (`llm/router.py:212`); наружу возвращается обычный
разобранный объект, и стадия о втором оплаченном вызове не узнаёт никак.
Считать повторы можно двумя способами: заставить роутер возвращать их число —
это правка `llm/router.py`, файла, которого **нет** в списке файлов Т-26, то
есть настоящий выход за границы; либо слушать журнал роутера — что и сделано,
целиком внутри `stages.py`. Исполнитель выбрал вариант, соблюдающий границы.

**Запретные области не тронуты** (проверено грепом по диффу): `batch_size` — 
только переиндентированные существующие строки; `prompts/scorer.md` в диффе
отсутствует; `relevance` — только переиндентация и данные нового теста;
параллельного запуска батчей нет, цикл остался последовательным.

## Строка печатается всегда — проверено запуском, а не рассуждением

- пустой вход → `скоринг: батчей 0, повторов по лимиту 0, время стадии 0.0 с`;
- отказ батча (`Exception`) → строка печатается, `батчей 1`;
- стоп-кран (`CostLimitExceededError`) → строка печатается **и** исключение
  выходит наружу: инвариант №5 соблюдён в обе стороны — отказ не роняет молча и
  не скрывается;
- слушатель журнала снимается: `handlers left on app.llm.router: []`, утечки
  между стадиями нет.

## Эскалация роутера цела и вернулась в роль страховки

Поведение сверено с кодом, а не с текстом теста: `llm/router.py:198-215` —
`budget = max_tokens`, при `_looks_truncated` → `budget *= 2` и повторный вызов.
При 16000 второй вызов уходит с 32000, что и утверждает тест
(`limits == [16000, 32000]`). Косвенное подтверждение: под мутацией (а) тот же
тест показал фактические `[8000, 16000]`.

## Советы, не блокирующие

1. **`stages.py:536-538` — счётчик слепнет молча при смене уровня журнала.**
   Если конфигурация логирования поднимет уровень `app.llm.router` выше
   `WARNING` или сработает `logging.disable`, запись не родится и строка навечно
   покажет «повторов 0» — ровно та неотличимость, против которой строка и
   вводится. Тестом не закрыто. **На прогоне Т-29 сверить число в строке учёта
   с числом `WARNING`-записей роутера в том же журнале.**
2. **`stages.py:559-561` — счётчик привязан к module-level логгеру.** Сегодня
   безопасно: скоринг вызывается один раз за прогон, фильтр по имени стадии
   закреплён тестом. Сработает только при параллельном скоринге, который задача
   сознательно откладывает.
3. **`stages.py:586-606`** — при переформатировании комментария Т-13 выпала
   фраза о том, как считалась вся семья лимитов («на 4000 обрывалось… 8000 =
   1 660 на ответ плюс ≈6 300 на рассуждение»). Для 16000 эмпирическое
   обоснование сохранено.
4. **`tests/test_stages.py:1327-1335`** — значение времени не утверждается,
   проверяется только подстрока. Таймер, стартовавший не в том месте, тесты не
   уронит. Известный предел покрытия.
