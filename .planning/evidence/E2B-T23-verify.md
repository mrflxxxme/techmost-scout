## Разметка кандидата типом — обратная сторона проверена перебором

Диспетчер оркестратора отсеивает формулировку, чей тип не перечислен в
`adapter.source_types`. Перебор **всех** членов `SourceType` против адаптера:

```
publication → False   patent → False   grant → False   org → False
showcase    → False   web    → True    contest → True
```

До разбора доходят ровно два типа. Health-проба жёстко задаёт `WEB`, дефолт
сигнатуры — тоже `WEB`, поэтому старые вызовы поведения не меняют. **Веб-кандидат
неожиданного типа не получает.**

Побочно: при `needs_extraction = True` разбор адаптера служит откатом при
падении экстрактора, а экстрактор размечает выдачу тем же типом запроса — оба
пути теперь дают один тип.

## Порядок сужения — обе стороны прогнаны

```
CONTEST со словом «грант» внутри:  конкурсных=7  грантовых=0
WEB грантовый:                     конкурсных=0  грантовых=2
WEB обычный:                       не сужается
```

Конкурсная формулировка реестров РНФ и ФСИ не получает даже со словом «грант» в
тексте, грантовая не получает площадок.

**Зафиксированный факт, не критерий:** конкурсная ветка стоит до проверки
контура, поэтому `contest` с `lang=en` в мировом контуре тоже сужается по
площадкам. Оба промпта задают по `contest` ровно один русский запрос, так что
сегодня это недостижимо.

## Слепота старого теста подтверждена мутацией

При мутации (в) (`max_queries` по умолчанию = 9):

```
старый test_предел_платных_запросов_на_прогон   → 1 passed   ← слеп
новый  test_конкурсные_формулировки_не_...      → 1 failed, assert 7 == 6
```

Причина в коде теста: `make_adapter(client, max_queries=6)` — предел задаётся
**явно**, поэтому изменение умолчания проходит мимо. Чужой тест исполнителем не
тронут (§3), правки в диффе только ниже строки 306.

**Установленный факт для ворот**, а не подозрение.
