## Блокирующая находка цикла 1 закрыта

`docs/deploy.md`, раздел 2, полностью переписан на два рабочих способа
клонирования приватного репозитория:

- **Способ 1 (SSH deploy-ключ, только чтение).** Порядок команд корректен и
  не опирается на результат более позднего шага — именно то, что было
  затребовано к проверке: ключ генерируется (`ssh-keygen`), его публичная
  часть добавляется в GitHub **до** клонирования, а сам `git clone` использует
  `GIT_SSH_COMMAND="ssh -i ~/.ssh/techmost-scout-deploy -o
  IdentitiesOnly=yes"` — переменную окружения, а не `git config
  core.sshCommand`, которую в пустом каталоге поставить было бы нельзя (в
  каталоге ещё нет `.git/`). `git config core.sshCommand` появляется только
  **после** `cd techmost-scout`, то есть после того, как репозиторий уже
  существует, — ловушка, названная в задаче цикла 2, обойдена верно. Флаг
  `-o IdentitiesOnly=yes` корректен: без него ssh мог бы сначала предложить
  другие ключи агента.
- **Способ 2 (fine-grained PAT в URL).** Токен подставляется прямо в URL
  клонирования; документ прямо предупреждает о двух местах утечки —
  истории оболочки (та же оговорка, что и для пароля Caddy в разделе 4,
  включая `history -d`/`history -c`) и `.git/config` репозитория (адрес
  `origin` содержит токен в открытом виде), с шагом, как убрать токен из
  `origin` при отзыве. Оба предупреждения проверены построчно — оба
  присутствуют, ни один не описан как «сам собой решится».

Раздел 1 «Что нужно заранее» получил пункт «Доступ к репозиторию» (сам факт
приватности назван явно, без забегания в способ аутентификации) и пункт про
доустановку `git` на минимальных образах VPS — оба совета цикла 1 закрыты.

## Раздел 8 (обновление версии) — согласованность способов проверена

Раздел 8 не называет конкретный адрес `origin`, а описывает механизм для
обоих способов сразу: при SSH — `git config core.sshCommand` сохранён в
`.git/config` репозитория с шага клонирования и подхватывается автоматически
любой последующей git-командой независимо от текущего подкаталога; при
токене — сам токен уже живёт в адресе `origin`, повторный ввод не нужен. Оба
утверждения проверены как факты, а не как заявления: `git config` со
scope по умолчанию (без `--global`) действительно пишет в
`<repo>/.git/config`, и `git pull`, запущенный из `techmost-scout/docker`
(подкаталога, а не корня репозитория — ровно тот сценарий, который
установлен конвенцией документа сразу после обоих способов клонирования),
использует конфигурацию того же репозитория независимо от глубины cwd —
несовпадения адресов между разделами 2 и 8 нет, скрытого отказа не будет.
