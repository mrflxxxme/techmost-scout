## Советы (не блокируют)

1. **Выживающий мутант: тест не отличает предел 500 от 499.** Геометрия входа
   выбрана так, что на границе среза стоит пробел (индекс 499), а перед ним
   точка (498). Из-за этого `raw[:500].rstrip()` и `raw[:499].rstrip()` дают
   один результат, и подмена `_FALLBACK_SUMMARY_LIMIT = 500` на `499` проходит
   все четыре утверждения теста — воспроизведено. Наблюдаемый контракт («не
   длиннее 500, многоточие, без висящего пробела») тест держит, поэтому это не
   дефект. Точную привязку дал бы второй вход с непробельным знаком на границе
   либо сверка со `stages._FALLBACK_SUMMARY_LIMIT` вместо литерала.
2. **Числа 500 и 499 в утверждениях отвязаны от константы.** Изменение
   `_FALLBACK_SUMMARY_LIMIT` обрушит тест громко, а не тихо, — это приемлемо и
   даже полезно. Но комментария об этом нет, и тот, кто будет менять предел,
   может «поправить» литерал вместо разбора.
3. **Совет 2 цикла 1 обоснованно не взят.** `tests/test_stages.py` не входит в
   список файлов Т-2; взятие было бы выходом за границы задачи (инвариант №9).
4. **Предсуществующий `httpx` в `backend/app/cli.py:16,93`** (команда «доктор»,
   сборка общего `AsyncClient` для адаптеров). По букве способа проверки
   инварианта №6 это попадание вне `llm/`, `search/` и оркестратора. К Т-2 не
   относится: присутствует уже в `d1978a7^`, в дельту не входит. Развилка —
   либо отдельная задача на вынос сборки клиента, либо уточнение формулировки
   №6 (композиционный корень CLI — тот же случай, что оркестратор). Разговор с
   владельцем, а не тихий обход.

### Тесты способны покраснеть — проверено по существу

Реализация (`stages.py:156-159`):

```python
summary = raw_text.strip()
if len(summary) > _FALLBACK_SUMMARY_LIMIT:      # 500
    summary = summary[:_FALLBACK_SUMMARY_LIMIT].rstrip() + "…"
return Brief(industry=industry_hint, task_summary=summary or "не указано")
```

Разбор подозрительного утверждения `summary[:-1] == _LONG_TASK_TEXT[:499]`:
**формулу реализации оно не воспроизводит.** Реализация режет по `[:500]` и
затем зовёт `rstrip()`; утверждение режет по литеральному `[:499]` и `rstrip()`
не зовёт. Это независимо вычисленное ожидаемое значение, а не переписанный код.
Тавтологий вида `len(x) == len(x)` в тестах нет.

Тест обрезки держится на четырёх независимых точках: `endswith("…")`,
`len == 500`, `summary[-2] != " "`, совпадение префикса с `[:499]`.

### Мутационная проверка — воспроизведена независимо

| Вариант | `len` | `endswith("…")` | `[-2] != " "` | `[:-1] == T[:499]` | Итог |
|---|---|---|---|---|---|
| реализация как есть | 500 | True | True | True | зелёный |
| без `rstrip()` | **501** | True | **False** | **False** | падают 3 утверждения |
| предел 499 вместо 500 | 500 | True | True | True | **мутант выживает** (совет 1) |

Пустой и пробельный вход: реализация → `"не указано"`; мутант `or ""` → `""`
для обоих параметров, падают оба. Заявление исполнителя подтверждено.
Геометрия подтверждена численно: `len(_PHRASE_50) == 50`,
`len(_LONG_TASK_TEXT) == 600`, `T[498] == '.'`, `T[499] == ' '`.

### Предусловия на геометрию входа — защищают

Все четыре предусловия сверяются с **литералами**, а не с выражениями,
производными от той же фразы, поэтому разъехаться вместе с правкой фразы не
могут: правка `_PHRASE_50` роняет предусловие с внятным сообщением, а не
превращает тест в зелёный ноль.

### Тесты не вакуумны

`_RecordingPipeline` ставится autouse-фикстурой, она же обнуляет `captured` на
каждый тест; оба новых теста читают `captured[0]` — при неотработавшем
пайплайне был бы `IndexError`, а не молчаливый пропуск. В
`test_pipeline_resilience.py` соседний тест через тот же помощник утверждает
`len(captured) == 1`, то есть проводка помощника доказана, и `assert captured
== []` в новом тесте содержательно.

### Зеркальный тест на `CostLimitExceededError` — корректен

`pytest.raises(CostLimitExceededError)` обёрнут **вокруг** `await
cli._run(...)`, то есть исключение ловится снаружи — проброс, а не гашение
внутри. Путь: `interactive=True` → `run_intake` даёт вопрос → `typer.prompt`
подменён → `refine_brief` бросает → `cli.py:205-206` `except
CostLimitExceededError: raise`. Плюс `captured == []` — пайплайн не запускался.
Оба места вызова стоп-крана (РЕШ-45) под тестом.
