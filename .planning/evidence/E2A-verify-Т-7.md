## Почему FAIL

Единственная причина — критерий 5 на интерпретаторе с pydantic-settings 2.9.1.
По условию верификации расхождение между двумя законными интерпретаторами само
по себе есть провал: набор обязан быть зелёным на обоих.

Целевые файлы задачи (критерии 1–3) на 2.9.1 проходят. То есть **узкая починка
цикла 2 своё дело сделала** — падавшие три теста кэша зелены на обеих версиях,
и мутация «вернуть передачу ключа по имени поля» их роняет. Провал критерия 5
вызван не кодом Т-7.

## Замер оркестратора: причина не в интерпретаторе

Верификатор назвал замедление открытым вопросом. Оркестратор сузил его парным
замером — **тот же самый системный интерпретатор**, разница в одной строке
настроек:

```
системный python, копия дерева с populate_by_name=True   →  370 passed за 80,0 с
системный python, дерево как есть                        →  не завершился за 300 с
```

Отсюда рабочая гипотеза: на 2.9.1 фикстура `settings` (`tests/conftest.py`)
отдаёт пустые ключи по ВСЕМ четырём полям, потому что передаёт их по имени поля
при заданном `validation_alias` и выключенном `populate_by_name` (см. РЕШ-63).
Часть тестов уходит на пути обработки «ключ не задан» с повторами и паузами,
что и даёт кратное замедление. Это не отказ кода Т-7, а следствие того же
дефекта оснастки, ради которого владелец завёл отдельную задачу.

Замер с разбивкой по длительности тестов запущен отдельно — он должен назвать
конкретные тесты, дающие замедление, и уточнить объём вынесенной задачи.
