## Пометка оркестратора о глубине этой верификации

Отчёт выше в основном **прогоняет уже написанные тесты**, а не собирает
независимые стенды. Ровно этот способ проверки дважды пропустил блокирующее:
тесты закрепляли ожидаемую строку, а не факт. Поэтому проверки по
первоисточникам сделаны отдельно и приводятся здесь фактическим выводом.

**БЛОК-3 — ссылка открывается (оркестратор, curl к первоисточнику):**
```
EA026963B1      → HTTP 200, <title>EA026963B1 - Система для выявления и
                  обследования течения беременности сельскохозяйственного животного
EA26963B1       → HTTP 404   (то, что давала первая волна)
EA0000026963B1  → HTTP 404   (то, что было до правок)
```
Ревью Э4-П5 независимо проверило по реальным номерам всех шести офисов базы:
EA, RU, WO, US, SU открываются (200); BY не открывается ни в одном формате —
открытый вопрос владельцу, задачей сознательно не тронут.

**БЛОК-4 — строка вернулась в клиентские документы (оркестратор, выгрузка
запроса №8 командой `scout export` на слитой ветке):**
