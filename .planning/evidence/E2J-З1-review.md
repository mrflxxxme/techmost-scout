   выдачи arXiv, стоп-слова и прочее из «границ» не тронуты.

2. **Правка по существу.** `arxiv.py:26-27`:
   `API_URL = "https://export.arxiv.org/api/query"` с однострочным
   комментарием о причине (прокси режет http). Namespace-константа XML
   `NS = {"atom": "http://www.w3.org/2005/Atom"}` (строка 28) не тронута —
   верно, это не URL запроса. Проверено, что реальный вызов идёт именно через
   эту константу: `self._client.get(API_URL, params=params)` — конкатенации
   или сборки URL из окружения нет, страж не может быть обманут скрытой
   подменой адреса.

3. **Страж не фиктивный, проверено придирчиво.** Тест
   `test_arxiv_api_url_только_https` (tests/test_search_failures.py:113-117)
   импортирует `API_URL` напрямую из модуля (`from app.search.arxiv import
   API_URL as ARXIV_API_URL`, строка 31) и утверждает
   `ARXIV_API_URL.startswith("https://")`. Это прямая проверка константы,
   которую использует боевой код — не respx-заглушка, которую можно
   случайно не заметить при несовпадении URL. Способов обмана (конкатенация,
   переменная окружения, второй похожий URL) не найдено: адрес запроса
   единственный, задаётся одной строкой, используется в одном месте.

4. **Мутация воспроизведена вручную** (не поверил заявлению на слово):
   временно вернул `http://` в `arxiv.py`, прогнал именно этот тест —
   упал:
   ```
   FAILED tests/test_search_failures.py::test_arxiv_api_url_только_https
   AssertionError: assert False
    +  where False = 'http://export.arxiv.org/api/query'.startswith('https://')
   ```
   Дерево возвращено в исходное состояние (`git checkout -- backend/app/search/arxiv.py`),
   `git status --short` после отката пуст.

5. **Respx-подмены переведены, старых http-заглушек не осталось.** Все
   существующие respx-тесты arXiv (`test_arxiv_500_поднимает_searcherror`,
   `..._нечитаемое_тело...`, `..._без_совпадений...`, `..._pdf_url...`)
   используют `respx.get(ARXIV_API_URL)` — тот же импортированный
   символ, поэтому автоматически подхватили https и не «молча» перестали
   матчиться. Единственные вхождения `http://` в файле — внутри тестовых
   фикстур Atom-ответа (`xmlns="http://www.w3.org/2005/Atom"` и
   `<id>http://arxiv.org/abs/...` — это данные внутри ответа сервера,
   идентификатор статьи и namespace XML, а не адрес запроса) — их трогать
   не требовалось и не следовало.

6. **Ничего лишнего в diff.** Единственный не-кодовый файл во втором
   коммите — собственный handoff исполнителя, что и ожидается.
