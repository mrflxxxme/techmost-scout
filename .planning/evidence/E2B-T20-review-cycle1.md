## Блокирующее: тест критерия приёмки 3 сам слеп (DLG-1)

`tests/test_metrics.py:142`, `test_max_relevance_matches_calibration_line`.

Критерий 3 требует: «максимум `relevance` из измерителя совпадает с максимумом
из строки калибровки на одних и тех же данных». Единственный способ этим двум
путям разойтись — разная обработка нейтральных оценок (`metrics.model_relevance`
против `stages._model_relevance`). Расхождение проявляется **только когда
максимум оценок модели ниже 5**, потому что нейтральная оценка — ровно пятёрка.

Тест берёт набор с максимумом **9**. Доказано мутацией: под мутацией (б) падают
три теста, а этот **остаётся зелёным**. Проверка критерия 3 критерий 3 не
проверяет — она утверждает, что девять равно девяти двумя способами.

Тот же класс дефекта исполнитель честно нашёл и починил у соседнего теста,
добавив набор с максимумом 4. Соседний тест в том же файле, с теми же данными,
остался нетронутым.

**Цена пропуска:** приёмка Т-30 будет читать число из строки калибровки и число
из измерителя. Если они разойдутся на выдаче агропрома (максимум 4, отказавший
батч) — ни один тест этого не поймает.

## Ответы на вопросы оркестратора

**Приватное имя `stages._has_neutral_score` — приемлемо.** Единственный держатель
знания о нейтральной оценке — стадия скоринга; вторая копия этого знания в
оркестраторе есть ровно тот дефект, который проект уже проходил на текстовой
пометке. Обращение к приватному имени честнее дублирования. Для Т-21, которая
правит `stages.py` штатно: публичный псевдоним — правка на две строки.

**Судьба по ключу склейки корректна и безопасна по построению:** `scored`
получается из `deduplicate`, который кладёт кандидатов в словарь ровно по
`dedup_key()` — дублей ключа быть не может. **Но риск смещается в Т-21:** если
второй проход сложит в один список кандидатов обоих проходов, повтор ключа
станет возможен, и тогда `selected` пометятся **обе** строки, хотя отбор взял
одну.

**`plan_log` обязателен (РЕШ-89) — выполнено.** Ветки `if plan_log is not None`
не осталось, ни у одного из трёх параметров нет значения по умолчанию, оба
тестовых вызова починены. Мутация «не передали список» теперь падает `TypeError`
на входе, а не проходит молча.

   с другим на Т-30 — получить долю 1,0 на исправном прогоне. **Взято в цикл 2.**
5. **Для Т-21:** звать `candidate_records` отдельно на каждый проход со своим
   `pass_no`, иначе повторный `dedup_key` пометит `selected` все строки с этим
   ключом.
