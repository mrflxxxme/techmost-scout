# План: JSON-API и поля экосистемы (Э-39 экосистемы, лёгкий режим РЕШ-244)

Закреплён 17 октября 2026. Основание: `docs/SPEC.md` §7а (Э6-1, Э6-4, Э6-5),
решения РЕШ-238…245, контракт `schemas/launch-context.schema.json`
репозитория `mrflxxxme/ecosystem` (версия `1.0`). Режим «Наука» не меняется ни
в одной стадии; слой аналогов, фильтр стран, `LeadEvent` и экспресс-скан — не
здесь (после грилла этапа 6).

Рабочий вопрос РЕШ-244: может ли правка пропустить к потребителю API факт без
ссылки? Нет — JSON отдаёт тот же клиентский вид, что печать, и только после
вердикта эксперта. Поэтому лёгкий режим: один цикл ревью, короткий ADR
(РЕШ-250), верификация и аудит.

## А1. Поля брифа `region_code`, `need_id`, `mode` (часть Э6-1)

**Файлы.** `backend/app/schemas.py`, `backend/app/models.py`, `backend/app/db.py`
(если схема базы догоняется там), `backend/app/web/brief_store.py`.

**Критерии.**
1. `Brief.region_code: str | None` — код субъекта ФНС, ровно 2 цифры
   (`^[0-9]{2}$`; Э-48 экосистемы: 83 — НАО, 86 — ХМАО, 89 — ЯНАО; справочник
   RADAR `config/geo/regions.csv`), иначе ошибка валидации;
   `Brief.need_id: str | None` — стабильный ID таксономии RADAR v1.0.0
   (`^[a-z][a-z0-9_]{1,63}$`, например `restaurants_cafes`);
   `Brief.mode: Literal["business", "gov"] = "business"`.
2. Поля сохраняются в строку `briefs` и читаются обратно (`save_brief` /
   `load_brief`); существующая база без новых колонок открывается и получает
   их тем же способом, каким проект уже догоняет схему.
3. Поля не попадают ни в один промпт и не меняют ни одну стадию: модель их не
   заполняет, они приходят из `LaunchContext`. Метки в `prompts/*.md` не
   добавляются.

## А2. JSON-выгрузка (часть Э6-4)

**Файлы.** `backend/app/export/json.py` (новый), при необходимости
`backend/app/cli.py` / `backend/app/cli_export.py` (`scout export --json`).

**Критерии.**
1. Функция строит словарь из того же `ExportView` (`build_export_view`), что
   печать: видимость карточек — по `verdicts`, у каждого факта `evidence` с URL.
2. В корне `schema_version: "1.0"`, номер запроса, бриф (с новыми полями),
   карточки, конкурсный класс, сводка, `sources_unavailable`.
3. Тот же замок черновика, что у PDF/DOCX (РЕШ-199): без вердикта эксперта
   выгрузки нет.

## А3. JSON-API `/api/v1` (часть Э6-5)

**Файлы.** `backend/app/web/routes/api_v1.py` (новый), `backend/app/main.py`,
`backend/app/config.py`, `docker/Caddyfile`, `docs/deploy.md`, `.env.example`.

**Критерии.**
1. Ключи приложений только из окружения: `SCOUT_API_KEYS=имя:ключ,имя2:ключ2`
   (`SecretStr`). Пусто — API выключен, любой вызов 401/503. Ключ — заголовком
   `Authorization: Bearer …` или `X-API-Key`; сравнение `secrets.compare_digest`.
   Ключ не пишется в лог и в ответ.
2. Роутер `/api/v1` не под basic auth интерфейса, а под ключом приложения.
   `docker/Caddyfile` пропускает `/api/v1/*` без `basic_auth`; для edge-блока —
   абзац в `docs/deploy.md` §11 (применение на сервере — шаг владельца).
3. `POST /api/v1/requests` — тело `{schema_version: "1.0", task, industry?,
   context?: {mode?, region?: {code_fns}, need?: {id}, source?}}` по контракту
   `LaunchContext`. Текст проверяется на обезличивание (`app.anonymize`); при
   риске — 422 без эха найденного. Запрос создаётся, прогон идёт в фоне без
   вопросов (как `scout run --no-interactive`), регистрируется там же, где
   прогоны веба. Ответ 202: `request_id`, статус, ссылки на статус и отчёт.
   Стоп-кран 20 ₽ (РЕШ-46) действует как везде.
4. `GET /api/v1/requests/{id}` — `schema_version`, машинный статус и подпись,
   признак «проверен экспертом», готов ли отчёт. Стоимость не отдаётся.
5. `GET /api/v1/requests/{id}/report` — JSON из А2 после вердикта эксперта;
   до него 409 `awaiting_validation`. Черновик через API не отдаётся ни в
   каком режиме (инвариант 2).
6. Приложение видит только свои запросы (колонка-владелец на `requests`);
   чужой или несуществующий номер — одинаковый 404.
7. Ограничение частоты в памяти процесса, на приложение: запуски
   (`API_RATE_LIMIT_RUNS_PER_HOUR`, по умолчанию 5) и чтения
   (`API_RATE_LIMIT_READS_PER_MINUTE`, по умолчанию 60); сверх — 429 с
   `Retry-After`.

## Проверка

`pytest` и `ruff check . && ruff format --check .` в Linux-контейнере
(`python:3.12-slim`); тесты без сети. Каждый критерий А1–А3 покрыт тестом, а
порча условия (ключ, лимит, изоляция приложений, замок вердикта, шаблон
`region_code`) краснит хотя бы один тест. Файлы продукта ≤ 500 строк.
