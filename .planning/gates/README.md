# Ворота этапов

Ворота — единственный чекпоинт, где в цикл входит владелец. Один осознанный
разбор с измеримыми порогами вместо десятка мелких одобрений по ходу работы
(§1, §8 `docs/team/CONVENTIONS.md`).

На каждый этап — один файл `<этап>.md`, имя совпадает с идентификатором этапа из
`docs/SPEC.md`: `Э1-2.md`, `Э2-1.md`, `Э5-2.md`. Файл заполняется на шаге 6
цикла командой `/team-gate <этап>` и подписывается на шаге 7.

Доказательства лежат отдельно, в `.planning/evidence/`, и называются по этапу:
`Э2-1-pytest.txt`, `Э2-1-ruff.txt`, `Э2-1-report.md`. Ворота на них ссылаются, а
не пересказывают: отчёт остаётся коротким, полный вывод команд доступен.

## Два правила

**Порог без ссылки на доказательство не пройден.** Пустая колонка
«Доказательство» — это статус «не пройден», а не «ок». В колонке «Факт» стоит
число или строка вывода команды: «52 passed», «3 из 6», «0 вызовов». Слова
«работает», «проверено», «в целом нормально» фактом не являются.

**Подпись ставит только владелец.** Ни один агент не пишет в раздел «Подпись
владельца» ничего, кроме `не подписано` и пустой даты. Заполнить чужую подпись —
нарушение процесса, а не ускорение; оркестратор на этом останавливается.

Из первого правила следует обращение с невыполнимыми проверками. Проверка,
которую нельзя выполнить сейчас, не растворяется в тексте: у неё появляется
идентификатор `DLG-N`, причина, конкретное действие владельца со ссылкой на
пункт `docs/deps-manual.md` и описание того, что происходит без неё. Этот
идентификатор виден в отчётах верификации и аудита.

Провал одних и тех же ворот дважды — не третья попытка, а разбор подхода с
владельцем (§4, §9).

## Шаблон файла ворот

```markdown
# Ворота этапа Э2-1 — обогащение по DOI

| Критерий | Порог | Факт | Доказательство | Статус |
|---|---|---|---|---|
| Тесты проходят | все | 52 passed | evidence/E2-1-pytest.txt | ок |
| Линтер чистый | 0 замечаний | 0 | evidence/E2-1-ruff.txt | ок |
| Обогащение работает | ≥1 карточка с цитируемостью | 3 из 6 | evidence/E2-1-report.md | ок |
| Платный поиск не вызывается | 0 вызовов | 0 | evidence/E2-1-calls.txt | ок |

## Отложено
- DLG-1: живая проверка на ключе OpenAlex — ключа нет. Действие владельца:
  получить ключ (docs/deps-manual.md, п. 5). Без него тест идёт на подменах.

## Подпись владельца
Статус: не подписано
Дата:
```

Пороги берутся из трёх мест и больше ниоткуда: критерии приёмки задач из
`.planning/PLAN.md`, блоки «Проверка» раздела `docs/SPEC.md` по этапу и
применимые пункты `docs/team/INVARIANTS.md`. Нарушение инварианта блокирует
ворота: оно не откладывается в `DLG-N` и не эскалируется.

Секреты в доказательства не попадают: команды и отчёты не печатают значения
ключей (инвариант 3). Вывод, содержащий ключ, обрезается до значимых строк.

## Как подписать

Владелец открывает файл, сверяет колонку «Доказательство» выборочно, затем
заменяет в разделе «Подпись владельца» статус на `подписано` и ставит дату.
После подписи файл не редактируется — этап закрыт, дальнейшие находки идут в
`JOURNAL.md` и в ворота следующего этапа.
