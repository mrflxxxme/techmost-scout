загрузка правил не нарушает. Ловушки загрузчика: UTF-8 с BOM, запятая,
переносы строк внутри кавычек (нужен настоящий CSV-парсер); файл структуры —
наоборот windows-1251 и точка с запятой.

**Оценка локального индекса:** SQLite + FTS5 по названию — **1,5–2,5 ГБ диска**
на релевантное подмножество, первичная загрузка **20–60 минут** машинного
времени, обновление — **полная перезаливка ~1 ГиБ ежемесячно**.

### ФИПС — открылся; рефераты и МПК бесплатны, но обход запрещён robots.txt

**17.08.2026 из рабочей сети `www1.fips.ru`, `www.fips.ru`, `fips.ru`,
`new.fips.ru` → 200** (14 августа было 403 DDoS-Guard). Живы подсистемы:
ИПС `/iiss/` (JSF/PrimeFaces), открытые реестры `/registers-web/`, официальные
публикации `/publication-web/`. Собственного раздела открытых данных у ФИПС
нет: `/opendata/` → 404.

**Регистрация для бесплатных баз не нужна:** «вход в поисковую систему (ИПС)
осуществляется без ввода логина/пароля». Бесплатно доступны **рефераты
российских изобретений на русском и английском с 1994 г.**, формулы полезных
моделей, программы ЭВМ / БД / топологии ИМС с 2013 г., полные тексты за
последние 3 бюллетеня, МПК 2026.01, МКТУ, МКПО. Платно: полный архив текстов,
товарные знаки, промобразцы, документы 1924–1993; «единицей оплаты считается
один запрос».

**Ограничение, определяющее путь:** `www1.fips.ru/robots.txt` (695 строк
правил) для `User-agent: *` содержит `Disallow: /iiss/`,
`Disallow: /registers-web/`, `Disallow: /publication-web/`,
`Disallow: /publication-ws/`. Все три нужные подсистемы закрыты для
автоматического обхода. По аналогии с границей по Google (РЕШ-55) программный
обход не строим. **ФИПС остаётся ручным инструментом оператора**, а
программный канал к российским рефератам и МПК называется «поисковая
платформа».

## Русскоязычные научные источники (разведка 16–17 августа 2026, РЕШ-68)

Повод: живой прогон 16 августа, запрос «гидроочистка дизельного топлива»,
отрасль «нефтепереработка» — `cyberleninka: 0` при верно выбранном наборе `cas`.
КиберЛенинка была единственным русскоязычным научным источником сборки.
Полное доказательство с фактическим выводом всех запросов —
`.planning/evidence/E2A-ru-science.md`.

### Почему КиберЛенинка дала ноль

Дело **не в отсутствии статей**: её собственный поиск находит по этому запросу
719 статей. Дело в OAI-PMH. Четыре причины, все проверены живыми запросами:

1. **`FRESHNESS_YEARS = 5` работает наоборот.** Адаптер шлёт `from=2021-01-01`,
   а `from` в OAI — нижняя граница `datestamp`, и записи идут по возрастанию.
   Курсор встаёт на **самую старую** партию под границей. Проверено: с
   `from=2021-01-01&set=cas` приходят 10 записей с `datestamp` 2021-01-03,
   все — один украинский биохимический журнал **с английскими названиями**.
   С `from=2026-01-01` тот же набор отдаёт русскую химию и полимеры. Строка
   активно вредит.
2. **`resumptionToken` теряет `set`.** Проверено: на странице 1 у записей стоит
   `<setSpec>cas</setSpec>`, на страницах 2 и 3 тега нет вовсе и приходит
   языкознание, право, политология. Из окна в 30 записей в наборе только 10.
3. **Записи бедные.** Проверено подсчётом на живом ответе: `dc:description` — 0,
   `dc:date` — 0, `dc:subject` — 0. Совпадение фактически ищется по названию.
4. **Наборы — внешние индексы, а не рубрики.** `cas` значит «попало в Chemical
   Abstracts», а не «про нефтепереработку». Отсюда биохимия и металловедение
   под вывеской «химия».

Гипотеза «имена наборов устарели» **снята**: `ListSets` вернул 3932 набора,
все 10 проверенных (`cas`, `agris`, `medline`, `pubmed`, `georef`, `rsci`,
`vak`, `zbmath`, `im`, `rinc`) на месте. Справочник Т-4 корректен.

Причины 2–4 со стороны клиента неустранимы: **OAI-PMH КиберЛенинки не является
поисковым интерфейсом**. Вкладываться в этот адаптер дальше смысла нет.

### Ключевые факты запросов

**OpenAlex — тот самый запрос, на котором был ноль:**

```
GET https://api.openalex.org/works?search=гидроочистка дизельного топлива
    &filter=language:ru,from_publication_date:2021-01-01&mailto=...
→ HTTP 200, meta.count = 5
  [2023] ОПТИМИЗАЦИИ УСТАНОВКИ ГИДРООЧИСТКИ ДИЗЕЛЬНОГО ТОПЛИВА ТОО «ПНХЗ»
         DOI = https://doi.org/10.48081/vgcj1519
```

Лимиты из заголовков живого ответа: `X-RateLimit-Limit: 1000`,
`X-RateLimit-Cost-USD: 0.001`, один запрос стоил 10 кредитов, сброс через
9518 с — то есть порядка 100 запросов на окно ≈2,6 ч. **Оговорка:** это
заголовки, а не документация; публично известная политика говорила про
100 000 запросов в сутки. Уточнить по `docs.openalex.org` до подключения.

**КиберЛенинка `/api/search`:** `{"mode":"articles","q":"<фраза>","size":5,"from":0}`
→ `found: 719`. Поля записи: `name`, `annotation`, `link`, `authors`, `year`,
`journal`, `journal_link`, `ocr`, `catalogs`. DOI в ответе **нет**.

**Грабля кодировки (сохранена, чтобы не наступить второй раз).** В PowerShell 5.1
`Invoke-WebRequest -Body <строка>` шлёт тело не в UTF-8, кириллица портится и
API честно отвечает `found: 0`. Рабочий вызов —
`-Body ([Text.Encoding]::UTF8.GetBytes($body))` с
`-ContentType 'application/json; charset=utf-8'`, ответ читать через
`[Text.Encoding]::UTF8.GetString($r.RawContentStream.ToArray())`. Поле `q` —
строка; массив даёт HTTP 400.

### Рекомендация

**Первым — OpenAlex с `language:ru`.** Стоит 0 рублей и одного адаптера по
образцу существующих: GET, JSON, три поля фильтра. Единственная нетривиальная
деталь — реферат приходит инвертированным индексом (`abstract_inverted_index`)
и разворачивается в текст десятком строк. Закрывает дыру фактически, а не на
бумаге: на живом запросе выдаёт русские статьи по теме с DOI и PDF. Ни ключа,
ни регистрации, ни `Disallow`, ни бот-защиты.

**Вторым — решение владельца по `/api/search` КиберЛенинки.** Технически это
лучший русскоязычный источник (719 против 5 на одном запросе, с рефератами), и
работы столько же — один POST. Мешает `Disallow: /api/` в `robots.txt`.
Бот-защиты там нет, обходить нечего, но запрет заявлен явно и переступается
только решением владельца. Рекомендуемый ход — **написать в КиберЛенинку и
попросить разрешение** на автоматический доступ для некоммерческого прототипа,
параллельно подключив OpenAlex: дыра закрыта сразу, а разрешение, если придёт,
даёт лучший источник легально.

**Чего не делать:** не вкладываться в OAI-адаптер (причины 2–4 неустранимы;
`FRESHNESS_YEARS = 5` убрать стоит — это одна строка и она вредит, но нуля это
не отменит), не идти в MVP в eLibrary (нет легального машинного канала), BASE
(регистрация IP) и вузовские OAI (нет поиска).
