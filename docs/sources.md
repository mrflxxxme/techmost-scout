### Три особенности класса, которых нет у публикаций и патентов

**1. Статус ИС определяет пригодность записи, а не примечание к ней.**
Разброс шире, чем по любому другому признаку:

- **права у команды по умолчанию** — Devpost: «Makers have and shall retain
  sole and exclusive title and ownership of all Software and Submissions…
  unless: (a) the Official Rules of a Hackathon state clearly that the Maker
  will be required to transfer property of the Submission»; XPRIZE: «XPRIZE
  claims no interest in any team's Intellectual Property»;
- **права уходят заказчику при выигрыше** — InnoCentive/Wazoku: «Theoretical
  IP Transfer Challenges require Solvers to transfer all rights to the
  Intellectual Property for which they are awarded»; российские корпоративные
  хакатоны — типовое отчуждение исключительного права партнёру, поставившему
  задачу;
- **обязательное раскрытие** — iGEM (Registry of Standard Biological Parts);
- **права у грантополучателя** — ФСИ («Старт», «УМНИК»).

Определить это автоматически нельзя: правило живёт в положении конкретного
конкурса, а не на платформе. Решение конкурса, чьи права ушли корпорации,
**вредно в карточке**: мы приводим клиента к разработчику, который не вправе
распоряжаться разработкой.

**2. Зрелость нельзя доверять модели.** Описание хакатонного проекта пишет
команда, и оно всегда звучит как готовый продукт. Стадию должен ставить
**код по типу источника**, как это уже сделано с `pdf_urls`:
хакатон — `lab`/`prototype`, TRL 2–4 потолок; iGEM и Kaggle — `lab`, TRL 2–3;
InnoCentive Theoretical — `lab`, RTP — `prototype` (TRL 4–5);
XPRIZE-финалист и Up Great — `prototype`/`pilot`, TRL 5–7.
**Призовое место зрелость не повышает** — первое место означает «лучше
остальных за те же 48 часов», а не «ближе к внедрению».

**3. Живость команды — сильная сторона класса.** У публикации в лучшем случае
есть аффилиация первого автора; у решения конкурса — имена участников, год и
часто ссылка на репозиторий. Дата последнего коммита читается через GitHub API
без ключа и это самый честный признак «жив или заброшен». У iGEM организация
и её сайт приходят прямо в API (`institutions[].name`, `website`). Прямых
контактов не отдаёт **ни одна** площадка — значит, `contact_leads` этого класса
это организация плюс имена плюс репозиторий, то есть зацепки, а не контакты.

Объём Devpost (202 не даёт тела), наличие рефератов проектов в API iGEM,

схема API Devfolio, условия HeroX и challenge.gov по ИС, дословная цитата из

разведки.

## Русскоязычные научные источники (разведка 16–17 августа 2026, РЕШ-68)

КиберЛенинка была единственным русскоязычным научным источником сборки.
Полное доказательство с фактическим выводом всех запросов —
`.planning/evidence/E2A-ru-science.md`.

### Почему КиберЛенинка дала ноль

Дело **не в отсутствии статей**: её собственный поиск находит по этому запросу
719 статей. Дело в OAI-PMH. Четыре причины, все проверены живыми запросами:

1. **`FRESHNESS_YEARS = 5` работает наоборот.** Адаптер шлёт `from=2021-01-01`,
   а `from` в OAI — нижняя граница `datestamp`, и записи идут по возрастанию.
   Курсор встаёт на **самую старую** партию под границей. Проверено: с
   `from=2021-01-01&set=cas` приходят 10 записей с `datestamp` 2021-01-03,
   все — один украинский биохимический журнал **с английскими названиями**.
   С `from=2026-01-01` тот же набор отдаёт русскую химию и полимеры. Строка
   активно вредит.
2. **`resumptionToken` теряет `set`.** Проверено: на странице 1 у записей стоит
   `<setSpec>cas</setSpec>`, на страницах 2 и 3 тега нет вовсе и приходит
   языкознание, право, политология. Из окна в 30 записей в наборе только 10.
3. **Записи бедные.** Проверено подсчётом на живом ответе: `dc:description` — 0,
   `dc:date` — 0, `dc:subject` — 0. Совпадение фактически ищется по названию.
4. **Наборы — внешние индексы, а не рубрики.** `cas` значит «попало в Chemical
   Abstracts», а не «про нефтепереработку». Отсюда биохимия и металловедение
   под вывеской «химия».

Гипотеза «имена наборов устарели» **снята**: `ListSets` вернул 3932 набора,
все 10 проверенных (`cas`, `agris`, `medline`, `pubmed`, `georef`, `rsci`,
`vak`, `zbmath`, `im`, `rinc`) на месте. Справочник Т-4 корректен.

Причины 2–4 со стороны клиента неустранимы: **OAI-PMH КиберЛенинки не является
поисковым интерфейсом**. Вкладываться в этот адаптер дальше смысла нет.

### Ключевые факты запросов

**OpenAlex — тот самый запрос, на котором был ноль:**

```
GET https://api.openalex.org/works?search=гидроочистка дизельного топлива
    &filter=language:ru,from_publication_date:2021-01-01&mailto=...
→ HTTP 200, meta.count = 5
  [2023] ОПТИМИЗАЦИИ УСТАНОВКИ ГИДРООЧИСТКИ ДИЗЕЛЬНОГО ТОПЛИВА ТОО «ПНХЗ»
         DOI = https://doi.org/10.48081/vgcj1519
```

Лимиты из заголовков живого ответа: `X-RateLimit-Limit: 1000`,
`X-RateLimit-Cost-USD: 0.001`, один запрос стоил 10 кредитов, сброс через
9518 с — то есть порядка 100 запросов на окно ≈2,6 ч. **Оговорка:** это
заголовки, а не документация; публично известная политика говорила про
100 000 запросов в сутки. Уточнить по `docs.openalex.org` до подключения.

**КиберЛенинка `/api/search`:** `{"mode":"articles","q":"<фраза>","size":5,"from":0}`
→ `found: 719`. Поля записи: `name`, `annotation`, `link`, `authors`, `year`,
`journal`, `journal_link`, `ocr`, `catalogs`. DOI в ответе **нет**.

**Грабля кодировки (сохранена, чтобы не наступить второй раз).** В PowerShell 5.1
`Invoke-WebRequest -Body <строка>` шлёт тело не в UTF-8, кириллица портится и
API честно отвечает `found: 0`. Рабочий вызов —
`-Body ([Text.Encoding]::UTF8.GetBytes($body))` с
`-ContentType 'application/json; charset=utf-8'`, ответ читать через
`[Text.Encoding]::UTF8.GetString($r.RawContentStream.ToArray())`. Поле `q` —
строка; массив даёт HTTP 400.

### Диагноз Э2-Ж: длина формулировки съедает выдачу

Живые контрольные вызовы 23 августа (тот же `User-Agent`, пауза 1 з/с) на
воротном прогоне Э2-Е, где `/api/search` неожиданно дал ноль по животноводству
— источнику ставилась не тема, а формулировка модели:

| Формулировка | Слов | `found` |
|---|---|---|
| «ультразвуковая диагностика супоросности свиноматок нейросеть» (как отдал планировщик) | 8 | **0** |
| «искусственный интеллект ультразвуковая диагностика свиноматок» | 6 | 1 (нерелевантно) |
| **«супоросность свиноматок УЗИ»** | **3** | **21, релевантные** |
| контроль «гидроочистка дизельного топлива» (нефтегаз, Э2-В) | 3 | 720 |

Полнотекстовый поиск склеивает термины запроса жёстко: чем длиннее и
многословнее формулировка, тем выше шанс «пере-уточнить» её до нуля — источник
жив, дело не в покрытии, а в форме запроса. Починка (задача З-2, Э2-Ж):
адаптер (`backend/app/search/cyberleninka.py`) при `found=0` на исходной
формулировке один раз повторяет запрос первыми 3–4 содержательными словами —
маленький стоп-словарь и порядок слов сохраняются, без обращения к модели и без
второго повтора. Обе формы и оба `found` пишутся в лог поиска, чтобы следующий
ноль читался из журнала прогона без повторных контрольных вызовов.

### Рекомендация

**Первым — OpenAlex с `language:ru`.** Стоит 0 рублей и одного адаптера по
образцу существующих: GET, JSON, три поля фильтра. Единственная нетривиальная
деталь — реферат приходит инвертированным индексом (`abstract_inverted_index`)
и разворачивается в текст десятком строк. Закрывает дыру фактически, а не на
бумаге: на живом запросе выдаёт русские статьи по теме с DOI и PDF. Ни ключа,
ни регистрации, ни `Disallow`, ни бот-защиты.

**Вторым — решение владельца по `/api/search` КиберЛенинки.** Технически это
лучший русскоязычный источник (719 против 5 на одном запросе, с рефератами), и
работы столько же — один POST. Мешает `Disallow: /api/` в `robots.txt`.
Бот-защиты там нет, обходить нечего, но запрет заявлен явно и переступается
только решением владельца. Рекомендуемый ход — **написать в КиберЛенинку и
попросить разрешение** на автоматический доступ для некоммерческого прототипа,
параллельно подключив OpenAlex: дыра закрыта сразу, а разрешение, если придёт,
даёт лучший источник легально.

**Чего не делать:** не вкладываться в OAI-адаптер (причины 2–4 неустранимы;
`FRESHNESS_YEARS = 5` убрать стоит — это одна строка и она вредит, но нуля это
не отменит), не идти в MVP в eLibrary (нет легального машинного канала), BASE
(регистрация IP) и вузовские OAI (нет поиска).

## EPO OPS (Espacenet) — разведка без кода (РЕШ-172, разведано 23 августа 2026)

Повод: РЕШ-172 — мировые патенты в волне Э2-Ж закрывает веб-контур
(`yandex_search.py`), PatentsView отклонён отдельно, но владелец хочет знать
факты о единственном сильном законном API-кандидате на будущее. Кода не
написано, заявка от имени владельца не подавалась. По коду до этой разведки
уже было известно немногое (`E2A-patents.md`, строка «EPO OPS»): ключ
самостоятельный бесплатный, `biblio.json` без ключа → 403, квота «4 ГБ/нед» —
без ссылки на первоисточник. Здесь квота и остальные четыре пункта карточки
проверены по документам EPO живыми запросами.

### 1. Условия регистрации и получения ключа

Регистрация — **самостоятельная, без одобрения владельцем API заранее**:
форма лежит открыто на `https://developers.epo.org/user/register` (проверено
живым GET, 200, форма отдаётся без входа в систему). Поля: логин, e-mail,
пароль, ФИО, название организации, отдел, адрес, страна (**Russia есть в
списке стран как обычная опция**, без пометок и ограничений), «What do you
need OPS for?» (варианты: обогащение своего ПО, внутренняя база, база для
третьих лиц, мониторинг, другое), отрасль, чекбоксы согласия с условиями,
подтверждения полномочий действовать от имени организации и роли
плательщика, плюс графическая CAPTCHA. Юридически регистрация — оферта:
согласно «Terms and conditions for use of the EPO's Open Patent Services
(OPS)», версия 2.0, 09.2017 (`developers.epo.org/sites/default/files/
terms_and_conditions_OPS%202.0%20EN_DE_FR.pdf`, живой GET 200), ст. 2:
«Acceptance of the present terms… by the user constitute an offer to the EPO
to conclude a contract… The EPO may accept this offer… The EPO will send its
acceptance by email» — то есть заявка не мгновенна по букве договора, EPO
формально акцептует её отдельным письмом; **сроки рассмотрения нигде не
названы числом** — не найдено ни на форме, ни в условиях. Для объёма свыше
бесплатного порога отдельно нужны платёжные реквизиты и подтверждение
(ст. 4.4–5.1), но это не блокирует бесплатный уровень.

Кто может подать заявку: физических или юридических ограничений в форме и
условиях не обнаружено — поле организации обязательно («Organisation/Company
name… on behalf of which the user is registering»), гражданство или страна
регистрации юрлица не фильтруются.

### 2. Лимиты бесплатного уровня

Число найдено на официальной странице «Fair use charter for the EPO's online
patent information products» (`https://www.epo.org/en/service-support/
ordering/fair-use`, живой GET 200, редиректов не было) дословно: **«Open
Patent Services (OPS, up to a weekly maximum of 4 GB) are available free of
charge 24 hours a day, 7 days a week»**. Там же по разделу «Automated
queries»: **«Downloading data via OPS is free of charge up to a maximum data
volume of 4 GB per week ("free threshold"). A week is a calendar week from
Monday, 00.00 hrs to Sunday, 24.00 hrs GMT»** — то же самое числом и словами
из «Terms and conditions» ст. 4.1–4.3 (там порог не назван цифрой, только
термином «free threshold», цифра — в прайс-листе и на странице fair use).

Throttling сверх объёма: **«the maximum traffic volume allowed is
approximately 1 Mbit per second»** — общий для OPS и European Publication
Server; «maximum data volume, connection rates and other access conditions
may vary depending on operational circumstances» — то есть лимит не жёстко
детерминирован документом. Рекомендация EPO для роботов: **«schedule data
retrieval activities by robots between 19.00 and 07.00 hrs GMT or at
weekends»** — вне часового пояса и режима нашего прогона это не блокер, но
влияет на планирование, если объём вырастет. За порогом — платная годовая
подписка по прайс-листу (`www.epo.org/service-support/ordering.html`, не
проверялся — не требуется при объёме карточек проекта). Для сверхбольших
объёмов EPO прямо предлагает писать на `patentdata@epo.org`.

Условия и порог могут быть изменены EPO в любой момент без согласия
пользователя, с уведомлением по почте и вступлением в силу через два месяца
(ст. 9 Terms) — то есть 4 ГБ/нед не гарантированы навсегда, но менее чем на
масштаб проекта («десятки запросов в месяц», CLAUDE.md) это некритично: одна
карточка биб. записи — единицы-десятки КБ, недельный порог кратно избыточен
для нашего объёма.

### 4. Формат поиска и полей ответа

По официально подтверждённым, но неполным сведениям (детальная спецификация
скрыта за регистрацией — см. ниже, честно): OPS описан на портале как «web
service which provides access to the EPO's raw data via a standardised XML
interface… using RESTful architecture» (`developers.epo.org`, живой GET);
данные приходят «from the EPO's bibliographic, worldwide legal event,
full-text and image databases… the same sources as the Espacenet and European
Patent Register data» (страница OPS на `www.epo.org`, живой GET). Тестовый
цикл описан в официальном PDF «How to test OPS Developers Area Swagger» (14
июня 2024, публично доступен по прямой ссылке с портала разработчика, живой
GET 200, 8 страниц): пользователь входит в Swagger конкретного сервиса,
«Enter your query, or just test with the example», меняет заголовок `Range`
для постраничной выдачи и жмёт «Execute» — то есть REST-запрос принимает
параметр запроса и диапазон, но сам PDF не даёт синтаксиса CQL и не
перечисляет поля.

**Полная спецификация формата запроса (CQL) и состава ответа (`biblio`,
`abstract`, `fulltext` и т. д.) НЕ НАЙДЕНА на общедоступных страницах.**
Ссылка «OPS User reference guide and other reference documentation»
(`developers.epo.org`, раздел «Documentation») ведёт на устаревший адрес
`www.epo.org/searching-for-patents/technical/espacenet/ops.html#tab3`,
который сейчас редиректит на общую страницу OPS без вкладки документации —
мёртвая ссылка, проверено живым запросом (получена та же общая страница
маркетинга, 628 КБ, без CQL). Раздел `/apis` тестовой area отдаёт 403 без
входа. Секция форума с примерами запросов не резолвится по DNS из сети
среды. Вывод по инварианту №1: **чего нет в источниках — «не найдено»**, а
не додумано по памяти о сторонних клиентах (`python-epo-ops-client` и т. п.,
уже упомянутых в `E2A-patents.md` как чужой стек). Формат `q`/CQL и точный
состав `biblio`/`abstract` подтверждаются только после регистрации, внутри
личного кабинета — это и есть первый практический шаг, если тема получит
продолжение.

### 5. Юридические условия

Из «Terms and conditions for use of the EPO's Open Patent Services (OPS)»,
версия 2.0, 09.2017 (полный текст on EN/DE/FR, читан целиком):

- Регистрация — оферта, договор заключается акцептом EPO по e-mail (ст. 2);
  бессрочный, каждая сторона расторгает с уведомлением за 3 месяца (ст. 8.1–2).
- Лицензия — **неисключительная, непередаваемая, всемирная**: разрешено
  «use and include these data in their own machine-readable databases,
  products and services… and may distribute the data as part of these
  products» (ст. 3.1) — то есть встраивать данные OPS в карточки продукта
  можно.
- **Прямой запрет: «Users are not permitted to make the data as such
  available to the public or to copy and/or distribute the data as such»**
  (ст. 3.2) — раздавать или публиковать сырые данные OPS как таковые
  (например, дамп ответов) нельзя; нарушение — единственно названное
  основание для расторжения без уведомления (ст. 8.3).
- Скачивание сверх бесплатного порога регулируется отдельно действующей
  **Fair use charter** (ст. 3.3, 4.2) — уже процитирована в п. 2.
- Роялти с продуктов, построенных на данных OPS, EPO не взимает (ст. 4.6).
- EPO не даёт гарантий полноты и точности данных, ответственность ограничена
  грубой небрежностью и умыслом (ст. 6–7.2) — источник как таковой не
  подтверждает достоверность фактов, только предоставляет данные, что
  согласуется с общим правилом системы «ни одного факта без ссылки»: карточка
  всё равно обязана ссылаться на первоисточник записи, а не на факт скачивания
  через OPS.
- Договор регулируется германским правом, споры — арбитраж в Мюнхене
  (ст. 10) — юрисдикционных препятствий для использования из России в самом
  тексте условий не описано.
- EPO может менять условия и порог в любой момент с уведомлением за два
  месяца (ст. 9, см. также п. 2).

Автоматическому клиенту разрешено: получать данные через REST/XML,
использовать в собственном ПО, обогащать карточки, распространять как часть
продукта. Запрещено: публиковать/раздавать сырые данные OPS как отдельный
датасет, обходить бесплатный порог несколькими договорами (ст. 8.3),
использовать графические интерфейсы Espacenet/Register для массовой выгрузки
(они для людей — раздел «Human users» fair use charter, порог 10
действий/мин на IP, автоматические запросы отправляются на REST OPS).

### Рекомендация

**Подключать после регистрации (шаг Х), не раньше.** Источник законный,
бесплатный порог (4 ГБ/нед) кратно избыточен для объёма проекта, лицензия
прямо разрешает встраивать данные в карточки продукта — по юридической части
и лимитам препятствий нет. Не подключаем прямо сейчас по двум причинам,
обе фактические, а не гипотетические:

1. **Ключ ещё не существует** — до заявки владельца код писать не на чем: без
   ключа `biblio.json` отдаёт 403 (подтверждено раньше, `E2A-patents.md`, и
   не переоткрывалось повторно сегодня — тратить квоту/минуты на воспроизведение
   уже подтверждённого 403 без ключа смысла нет).
2. **Формат запроса (CQL) и состав ответа не документированы публично** —
   спецификация открывается только после входа в личный кабинет
   разработчика. Писать адаптер вслепую, без реального просмотра полей
   ответа, означает гадать на живых, но недокументированных полях — риск
   для инварианта №1 (факты без проверенного источника).

Патентный веб-контур сейчас закрывает `yandex_search.py` (РЕШ-172, принято
владельцем). EPO OPS остаётся кандидатом следующей волны — сильнее и
устойчивее произвольного веб-поиска по патентам, но требует шага владельца,

### Шаги владельца (если тема получит продолжение)

1. Зарегистрироваться на `https://developers.epo.org/user/register`
   (пять минут, самостоятельно, без утверждения заранее по факту заполнения
   формы — фактический срок акцепта EPO по почте документами не назван).
2. После получения кредов — войти на `developers.epo.org`, создать тестовое
   приложение («dummy app» в «My Apps») и открыть раздел «Documentation» /
   Swagger в личном кабинете, чтобы увидеть настоящий синтаксис CQL и состав
   `biblio`/`abstract` (недоступно агенту без аккаунта).
3. Решить, кто в организации — плательщик по форме (поле «I confirm that I
   have selected the paying role…») — обязательный чекбокс формы независимо
   от того, планируется ли выход за бесплатный порог.
4. Сообщить агентам факт получения ключа — тогда РЕШ-172 может быть
   пересмотрено и задача на код (адаптер OPS) заведена отдельно, с
   тестами на подменах, как остальные источники.

Тот же список продублирован в `docs/deps-manual.md` новым пунктом.
