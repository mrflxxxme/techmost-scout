# Что нужно донести вручную

Перечень внешних зависимостей, которые не может закрыть ИИ-агент: везде нужны
ваши персональные данные, согласие с условиями или оплата. Всё остальное
(код, промпты, конфигурация, бесплатные источники без регистрации) уже в
репозитории или делается агентами по спецификации.

Статус на 9 августа 2026. После каждого пункта — как проверить: `scout doctor`
показывает результат по каждому ключу и источнику.

## Закрыто автоматически (проверено живыми вызовами 9 августа 2026)

### 1. GigaChat — основная модель — ✅ РАБОТАЕТ

`scout doctor`: «ок, модель GigaChat-2, потрачено 0.0012 ₽». Бесплатный тариф
подключён — 250 млн токенов Lite на 12 месяцев. Что было сделано:

- Ключ перенесён из TEAMLY_RU.
- Сертификаты НУЦ Минцифры оказались **уже установлены** в хранилище Windows
  (корневой и выпускающий). Скрипт `scripts/build_ca_bundle.py` достаёт их
  оттуда и склеивает с набором certifi в `data/ru_bundle.pem`;
  в `.env` прописано `GIGACHAT_CA_BUNDLE=data/ru_bundle.pem`.
- Найден и исправлен неверный адрес API: в публикациях фигурирует
  `api.giga.chat` как «новый базовый адрес», но он отдаёт 403 от nginx.
  Рабочий — `gigachat.devices.sberbank.ru/api/v1`, проверено живым вызовом
  (отдаёт список моделей: GigaChat, GigaChat-2, GigaChat-2-Pro, GigaChat-2-Max).

**Что делать, если перестанет работать:**
- Ошибка TLS `CERTIFICATE_VERIFY_FAILED` после переустановки системы →
  `.venv\Scripts\python.exe scripts\build_ca_bundle.py`. Если скрипт скажет,
  что сертификатов нет: скачать «Сертификаты для Windows» с
  https://www.gosuslugi.ru/crt, установить двойным щелчком, повторить.
- Ошибка 401 при авторизации → ключ отозван. developers.sber.ru → проект
  «GigaChat API» → сгенерировать ключ авторизации → в `.env`
  `GIGACHAT_AUTH_KEY`. Вход по Сбер ID.
- Кончился бесплатный лимит → там же докупить пакет (65 ₽ за 1 млн токенов)
  либо в `.env` переключить массовые стадии на DeepSeek одной правкой:
  `LLM_STAGE_ROUTES=intake:deepseek,planner:deepseek,...`

### 2. DeepSeek — качественные стадии — ✅ РАБОТАЕТ

`scout doctor`: «ок, модель deepseek-v4-flash». Следить только за **балансом**:
пополнение возможно лишь зарубежной картой или через посредника. При нуле
баланса система не встанет — стадии уйдут на GigaChat по резервному маршруту,
качество карточек просядет.

Попутно выяснено и учтено в коде: V4-Flash — рассуждающая модель, она тратит
токены на `reasoning_content` до того, как начнёт писать ответ. При скупом
лимите ответ приходит пустым. Провайдер это распознаёт и, если возможно,
достаёт JSON из рассуждений.

### 4. YandexGPT — аварийный резерв — ⚠️ нужен новый ключ (~5 минут)

`scout doctor`: «apikey has expired 2026-06-30». Ключ из TEAMLY_RU мёртв.
Сам выпустить не смог: `yc` CLI на машине настроен, но Яндекс перестал
принимать к обмену OAuth-токены, выданные после 1 июня 2026 («OAuth token …
is not supported for IAM token exchange») — нужна ваша авторизация в браузере.

**Вариант А, через браузер (проще):**
1. Открыть https://console.yandex.cloud → каталог `b1g74vf7snhebom5avhu`
   (он же уже прописан в `.env` как `YANDEX_CATALOG_ID`).
2. «Сервисные аккаунты» → создать, имя `scout-llm`.
3. Ему же назначить роль `ai.languageModels.user` на каталог.
4. В карточке аккаунта → «Создать новый ключ» → **API-ключ** (не статический
   ключ доступа и не авторизованный ключ). Скопировать секрет — он показывается
   один раз.
5. В `.env` строка `YANDEX_API_KEY=<секрет>`.
6. Проверить: `.venv\Scripts\scout.exe doctor` → yandex «ок».

**Вариант Б, через CLI (если предпочитаете терминал):**
```powershell
yc init                              # заново авторизоваться в браузере
yc iam service-account create --name scout-llm
yc resource-manager folder add-access-binding b1g74vf7snhebom5avhu --role ai.languageModels.user --service-account-name scout-llm
yc iam api-key create --service-account-name scout-llm
```
Секрет из последней команды → в `.env` в `YANDEX_API_KEY`.

Важно: у Yandex Cloud API-ключи с некоторого времени выпускаются с ограниченным
сроком. Если снова протухнет — `scout doctor` покажет это прямым текстом с датой.

Без этого ключа система полностью работоспособна: две модели из трёх отвечают.

### 5. OpenAlex — обогащение карточек по DOI (~1 минута)

Нужен к этапу Э2-1. С 13.02.2026 ключ обязателен, но бесплатен:
1. https://openalex.org → зарегистрироваться (только почта, без карты).
2. https://openalex.org/settings/api → сгенерировать ключ.
3. В `.env`: `OPENALEX_API_KEY=<ключ>`.

Используем только бесплатные запросы по DOI — их поиск платный ($1 за 1000
вызовов), и код намеренно к нему не обращается.

### 6. Semantic Scholar — свой ключ вместо общего пула (заявка, ответ днями)

Источник уже работает без ключа, но на общем лимите: в `doctor` периодически
видно 429. Заявка: https://www.semanticscholar.org/product/api → форма
(нужно указать цель использования). Ключ придёт на почту → `.env`
`SEMANTICSCHOLAR_API_KEY`. Нюанс: отзывается после ~60 дней неактивности.

### 8. Yandex Search API — поиск по сайтам институтов и грантам — ОБЯЗАТЕЛЕН к приёмке

Единственный платный источник (≈50–200 ₽ за 1000 запросов; в пайплайне жёсткий
лимит 6 запросов на прогон). Бесплатной замены нет: у Brave бесплатный тариф
закрыт в 02.2026. Нужен биллинг-аккаунт Yandex Cloud с картой → API-ключ →
`YANDEX_SEARCH_API_KEY`. В TEAMLY_RU этого ключа не было.

Ключ — предусловие приёмочных испытаний Э5-2 (РЕШ-13): без него недостижима
метрика покрытия ≥4 типов источников (гранты и организации ищутся только этим
каналом). Нужен к Э2-3, крайний срок — до Э5-2.

## Что НЕ нужно делать

- Регистрировать ничего для Crossref, arXiv, КиберЛенинки, открытых данных
  Роспатента — они работают без ключей, уже подключены.
- Покупать Perplexity/Anthropic для рантайма — при стратегии минимальной
  себестоимости они не используются (Claude остаётся инструментом разработки,
  а не частью продукта).
- Трогать Gemini, Groq, OpenRouter, Mistral — из РФ либо заблокированы, либо
  ненадёжны, либо требуют согласия на обучение на ваших данных.
- ЕГИСУ НИОКР (rosrid): API нет, гостевой поиск урезан, регистрация только для
  организаций — вернёмся, когда появится юрлицо.
