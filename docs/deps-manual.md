# Что нужно донести вручную

Перечень внешних зависимостей, которые не может закрыть ИИ-агент: везде нужны
ваши персональные данные, согласие с условиями или оплата. Всё остальное
(код, промпты, конфигурация, бесплатные источники без регистрации) уже в
репозитории или делается агентами по спецификации.

Статус на 11 августа 2026. Ключи живут в `.env` (файл в `.gitignore`); шаблон
`.env.example` коммитится и остаётся пустым — секретам там не место. Проверка:
`scout doctor` показывает результат по каждому ключу и источнику.

Ничего блокирующего сейчас нет. Открыт один пункт — ключ Google для мирового
веб-поиска (пункт 7, около десяти минут): без него система работает, но ищет
только по российскому контуру и научным базам.

## Закрыто (проверено живыми вызовами 11 августа 2026)

### 1. GigaChat — основная модель — ✅ РАБОТАЕТ

`scout doctor`: «ок, модель GigaChat-2, потрачено 0.0012 ₽». Бесплатный тариф
подключён — 250 млн токенов Lite на 12 месяцев. Что было сделано:

- Ключ перенесён из TEAMLY_RU.
- Сертификаты НУЦ Минцифры оказались **уже установлены** в хранилище Windows
  (корневой и выпускающий). Скрипт `scripts/build_ca_bundle.py` достаёт их
  оттуда и склеивает с набором certifi в `data/ru_bundle.pem`;
  в `.env` прописано `GIGACHAT_CA_BUNDLE=data/ru_bundle.pem`.
- Найден и исправлен неверный адрес API: в публикациях фигурирует
  `api.giga.chat` как «новый базовый адрес», но он отдаёт 403 от nginx.
  Рабочий — `gigachat.devices.sberbank.ru/api/v1`, проверено живым вызовом
  (отдаёт список моделей: GigaChat, GigaChat-2, GigaChat-2-Pro, GigaChat-2-Max).

**Что делать, если перестанет работать:**
- Ошибка TLS `CERTIFICATE_VERIFY_FAILED` после переустановки системы →
  `.venv\Scripts\python.exe scripts\build_ca_bundle.py`. Если скрипт скажет,
  что сертификатов нет: скачать «Сертификаты для Windows» с
  https://www.gosuslugi.ru/crt, установить двойным щелчком, повторить.
- Ошибка 401 при авторизации → ключ отозван. developers.sber.ru → проект
  «GigaChat API» → сгенерировать ключ авторизации → в `.env`
  `GIGACHAT_AUTH_KEY`. Вход по Сбер ID.
- Кончился бесплатный лимит → там же докупить пакет (65 ₽ за 1 млн токенов)
  либо в `.env` переключить массовые стадии на DeepSeek одной правкой:
  `LLM_STAGE_ROUTES=intake:deepseek,planner:deepseek,...`

## Требует вашего участия

### 7. Google — мировой веб — ⚙️ НУЖНЫ ДВА ЗНАЧЕНИЯ (~10 минут)

Адаптер написан и включается сам, как только оба значения окажутся в `.env`.
Он даёт то, чего не даёт Яндекс: университеты и институты за пределами РФ,
спин-оффы, англоязычные витрины технологий.

**Шаг 1, ключ API:**
1. https://console.cloud.google.com → создать проект (или взять существующий).
2. «APIs & Services» → «Library» → найти **Custom Search API** → «Enable».
3. «APIs & Services» → «Credentials» → «Create credentials» → «API key».
4. Скопировать → в `.env`: `GOOGLE_API_KEY=<ключ>`.

**Шаг 2, поисковая система:**
1. https://programmablesearchengine.google.com/controlpanel/create
2. Имя любое, например `techmost-scout`.
3. **Обязательно** выбрать режим «Search the entire web» («Искать по всему
   вебу»). Без него поиск идёт только по списку сайтов, заданному вручную, и
   мировой охват превращается в десяток закладок — это главная ошибка при
   настройке.
4. Создать → скопировать «Search engine ID» → в `.env`: `GOOGLE_CSE_ID=<id>`.

**Шаг 3, проверка:** `.venv\Scripts\scout.exe doctor` → строка `google_search`.
Проба тратит один платный запрос из суточной сотни — так и задумано: пустая
переменная и работающий ключ это разные вещи, на чём мы уже обжигались.

**Про деньги и лимит.** 100 запросов в сутки бесплатно, без привязки карты.
Сверх этого — 5 долларов за 1000, но для этого нужен биллинг Google Cloud,
который из РФ картой не оплатить. Поэтому исходим из ста запросов в сутки: при
6–10 формулировках на прогон это порядка десяти прогонов в день, для MVP
достаточно. Если упрёмся — сузим план поиска, а не будем искать обходные пути
оплаты.

## Изменённый подход: данные, а не ключи

### 11. Витрина партнёров — наполняется органически (РЕШ-11)

Разовой загрузки подготовленного CSV не будет. Источник или разработка,
показавшая себя на реальном запросе — в боевом прогоне или при тестировании, —
кладётся в витрину как побочный продукт работы. Витрина растёт из того, что
доказало полезность, а не из догадок о том, что пригодится.

Ручная загрузка `scout showcase файл.csv` остаётся как инструмент, но перестаёт
быть предварительным условием. Пустая витрина выдачу не ломает: `scout doctor`
показывает «записей в витрине: 0» и остальные источники работают.

Что нужно от нас: механизм захвата — чтобы удачная находка попадала в витрину
без отдельного ручного шага. Задача этапа Э2.

### 12. Задачи для приёмки — берутся с рынка (РЕШ-12)

Не из проблемных интервью Фазы 0, а живые открытые заявки: запросы компаний на
НИОКР, тендеры на исследовательские работы, задачи технологических конкурсов и
акселераторов. Требования: актуальные, отраслево релевантные (нефтегаз, фарма,
агропром), сформулированные посторонним человеком для своих целей.

Смысл — непредвзятость: такой запрос не подстроен под то, что система умеет.
Поиск таких заявок делают агенты, участие владельца не требуется. Валидатор для
оценки карточек (научный со-основатель или сдельный эксперт) по-прежнему нужен
к этапу Э5-2.

**Площадки, подтверждённые разведкой 11 августа 2026:**

- **Каталог запросов НАТТ** — https://digital-natt.ru/requests/ — основной
  источник. 492 активных технологических запроса, 35+ заказчиков: РЖД,
  Татнефть, НЛМК, ММК, Русагро, Росатом, Ростех. У запроса есть заказчик, дата,
  область применения и технологическое направление. Просмотр без регистрации
  (регистрация нужна только чтобы откликнуться). Формулировки ровно того типа,
  что нам нужен: «машинное зрение для считывания номеров на трубах и муфтах»
  (ТМК НТЦ), «роботизированное устройство выкармливания поросят» (Русагро).
- Тендеры на НИОКР: rostender.info, rts-tender.ru, закупки Транснефти. Годятся
  как второй слой — формулировки там юридические, а не инженерные.
- Акселераторы и техконкурсы: ФРИИ, «Технологии для завтра» (2035.university),
  агротех-программа Россельхозбанка. Третий слой, самый шумный.

Отраслевой охват НАТТ закрывает две наши отрасли из трёх сразу (нефтегаз —
Татнефть, агропром — Русагро); под фарму, вероятно, придётся идти в тендеры.

## Что НЕ нужно делать

- Регистрировать ничего для Crossref, arXiv, КиберЛенинки, открытых данных
  Роспатента — они работают без ключей, уже подключены.
- Покупать Perplexity/Anthropic для рантайма — при стратегии минимальной
  себестоимости они не используются (Claude остаётся инструментом разработки,
  а не частью продукта).
- Трогать Gemini, Groq, OpenRouter, Mistral — из РФ либо заблокированы, либо
  ненадёжны, либо требуют согласия на обучение на ваших данных.
- ЕГИСУ НИОКР (rosrid): API нет, гостевой поиск урезан, регистрация только для
  организаций — вернёмся, когда появится юрлицо.
- Класть ключи в `.env.example` — он коммитится в git. Только в `.env`.
